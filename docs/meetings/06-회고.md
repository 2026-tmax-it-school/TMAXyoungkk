## 1. 지금 상태

회고 발언을 준비하면서 PM과 QA 리드가 현재 파일로 세 명령을 다시 돌렸다. 테크리드는 tsc와 npm test를 다시 돌렸고 export는 final.json 기록을 따랐다.

| 항목 | 결과 |
| --- | --- |
| npx tsc --noEmit | exit 0, 오류 0건 |
| npm test | 585개 전부 통과(스위트 63, 실패 0, todo 0) |
| 웹 export | 성공. 번들 1개 1.5MB(index-29123b78…, 05 회의록과 해시 같음), ttf 4개 |
| 패키지 게이트 WP1~WP6 | 모두 통과(final.json 기록) |
| 기능 범위(추적표 38행) | 구현 34, 부분 4, 미구현 0. MVP 20행은 모두 구현 |
| 비기능(추적표 16행) | 구현 12, 부분 4 |
| 확정 결정 되돌림 | 0건(qa-decisions 테스트로 고정) |
| 명세 밖 기능 | 환율·정산 0건, react-native-maps 0건, 구글 제공자 0건 |

과제 문구에 적힌 시작 상태(459개 중 447 통과, 실패 6, todo 6, tsc 2건)는 지금 파일과 맞지 않는다. 늦어도 패키지 리뷰 반영(WPn-fix) 단계에서 이미 풀린 값이다. 이 회의록은 위 표의 수치를 기준으로 한다.

부분으로 남은 네 기능은 다음과 같다.

- FR-104 프로필 이미지 5MB, FR-701 사진 10MB: 압축 판정과 예상 크기 표시만 있다. services/photos/device.ts가 image-picker quality 1 고정이라 네이티브에서도 실제로 줄지 않는다. 결정 31과 코드가 어긋난다.
- FR-504 대중교통: 2차 배지와 모의 모델만 있다. 확정 결정대로 1단계는 도보·자동차다.
- 계정 탈퇴: 이미 만든 일기 문장에 탈퇴 멤버 닉네임이 남는다(Q2).

## 2. 잘된 점

1. **범위를 지켰다.** 기능 38행 가운데 미구현 0, MVP 20행 모두 구현이다. 명세 밖 기능은 만들지 않았고 확정 결정 4개(확정 버튼 없음·자동 선별, 1단계 도보·자동차, 국내 전용·SDK 중립, 게스트 세션 30일)를 되돌린 곳이 없다. 되돌리지 않았다는 사실을 말이 아니라 qa-decisions 테스트로 확인할 수 있다.
2. **순수 로직과 화면을 처음부터 나눴다.** core가 ui·react-native를 import하지 않는 경계를 foundation-core-boundary 테스트가 강제한다. 그래서 자동 선별, 경로 예산 100건, 24시간 캐시, Held-Karp 최적성, 도착 3분·50m, 지연 15분, 게스트 30일, 오프라인 큐 중복 같은 핵심 규칙이 모두 node 테스트로 잠겨 있고, 585개가 3초 안에 돈다. 명세 수치 경계는 정각과 ±1로 단언했고 무작위 성질 테스트(선별 60회, 수신 뒤섞기 50회, 경로 예산 20회)도 있다.
3. **골든 시나리오를 먼저 수치로 박았다.** 후보 14·확정 11·제외 3, 10/18 09:25 불국사 → 11:07 석굴암 → 12:57 교촌마을 한정식을 기반 단계에서 todo로 먼저 적어 두고 통합 때 풀었다. 여섯 패키지가 따로 개발했는데도 통합에서 한 번에 맞았고, 두 번 돌려도 같다. 대화 인식은 재현율 95.7%(45/47), 오탐 0%다.
4. **소유권과 게이트가 병렬 개발을 지켰다.** ownership.json 파일 단위 소유와 gate-scope.mjs가 사용량 한도로 끊긴 뒤에도 경계를 유지했다. 공유 파일 변경은 패키지가 직접 고치지 않고 요청으로 모았다가 통합에서 계약 A12로 한 번에 받았다. 계약과 부딪힌 요청 두 건은 근거를 적고 받지 않았다.
5. **코드 리뷰가 실제 결함을 잡았다.** 세 관점(명세·정확성·디자인) 리뷰가 211건(WP1 29, WP2 39, WP3 36, WP4 35, WP5 42, WP6 30)을 냈고 blocker·major는 모두 반영했다. WP4 '이 구간만'이 재정렬로 사라지던 blocker, FR-205 기점 승계 버그, WP5 취소 뒤 건너뜀처럼 리뷰가 없었으면 시연에서야 드러났을 문제다.
6. **끊겨도 이어할 수 있었다.** workflow-state 결과 파일 덕분에 여러 번 끊겨도 다음 단계가 이어받았다. 각 단계가 현재 파일을 먼저 읽고 판단해서, 낡은 과제 문구 때문에 이미 고친 것을 다시 고치는 일은 없었다.
7. **지우면 안 되는 것을 지우지 않았다.** git에 없는 유일한 사본인 legacy-v1은 삭제하지 않고 ../archive/legacy-v1로 옮겼다(import 0건).

## 3. 문제점

1. **화면을 한 번도 보지 않았다.** 가장 큰 구멍이다. 개발 서버 금지 규칙 때문에 모든 단계가 tsc·테스트·export로만 확인했고, 화면 눈 확인은 매번 다음 단계로 넘어가다 결국 아무도 하지 않았다. 390×844 렌더, 지도 렌더 2초, 네이티브 기기는 확인하지 않았다. 통합이 배치를 바꾼 9곳(01·04·05·08·10·11·13·21·22)이 가장 위험하다. 화면(.tsx)을 여는 테스트 네 개는 모두 소스 텍스트 검사이고 렌더링 테스트는 없다. "585개 전부 통과"는 화면 품질에 대해서는 아무것도 말해 주지 않는다.
2. **스토어가 테스트 사각지대다.** store/live.ts(845줄), store/trips.ts(685줄)를 포함한 zustand 스토어 4개가 AsyncStorage·react-native 의존 때문에 node에서 불리지 않는다. 테스트가 직접 import하는 src 파일은 200개 중 92개(어림값)이고, screens·store·navigation은 전부 밖이다. clearSessionPhotos 미호출, useCurrentTrip 멤버십 미확인 같은 결함은 리뷰와 grep으로만 찾았다. seedScenario 두 번 연속 실행도 테스트가 없다.
3. **실제 제공자를 한 번도 돌리지 않았다.** 카카오 로컬·카카오모빌리티·AI 프록시는 가짜 fetch로만 검증했다. 웹 CORS, 동시 요청 한도, 실제 응답 형식은 모른다. 국내 지도 SDK는 미선정이라 지도는 모의 SVG다. 여러 기기 실시간 동기화도 확인하지 않았고, 네트워크 끊김 감지는 시연 토글뿐이다.
4. **결정과 코드가 어긋난 채 늦게 드러났다.** 결정 31(네이티브에서 image-picker quality로 실제 압축)을 계획에만 적고 소유 패키지 인수 조건으로 옮기지 않았다. 코드는 quality 1 고정이고, 추적표 단계에서야 드러나 FR-104·FR-701이 부분으로 남았다.
5. **진행 상태 기록이 실제보다 늦었다.** 과제 문구의 시작 상태(459개·실패 6·tsc 2건)가 통합·QA·최종·회고까지 갱신되지 않았다. 매 단계가 "이미 풀려 있었다"를 확인하느라 시간을 썼다. 확인을 건너뛴 단계가 있었다면 잘못 판단했을 것이다. 최신 수치를 한곳에 두고 갱신하는 장치가 없었다.
6. **병렬 단계가 서로 다른 코드 상태를 봤다.** QA(명세 추적)가 통합 전 코드로 추적표를 쓰는 동안 통합은 같은 내용을 반영하고 있었다. 최종 단계에서 추적표 14곳을 다시 고쳤다. 순서(통합 → 추적) 문제다.
7. **주인 없는 산출물이 있었다.** plan.json qa.testTargets의 tests/integration-account-delete.test.ts를 QA와 통합이 서로 상대 몫으로 넘겼고, 릴리스 점검에서야 만들어졌다. QA가 새 테스트를 만들 때마다 FOUNDATION 소유 ownership.json을 건드려야 했던 것도 같은 문제다.
8. **넘긴 일이 구조 필드에 없었다.** WPn-fix.json 여섯 개의 openIssues가 모두 빈 배열이다. 넘긴 항목(공유 변경 요청, 팀 결정 대기)은 summary 본문에만 있어 통합이 문장을 읽어 골라내야 했다. 빈 openIssues는 "없음"이 아니라 "안 적음"이었다.
9. **공유 파일에 비용이 몰렸다.** ui·types·ports가 FOUNDATION 소유라 패키지가 필요한 토큰·prop을 직접 만들지 못하고 임시 타입이나 우회를 먼저 썼다. 통합 담당이 파일 50개 넘게 한꺼번에 고쳤고, 그 배치 변화는 눈으로 확인하지 못했다.
10. **일정 근거가 약하다.** WPn-build와 리뷰 파일 15개의 수정 시각이 모두 9/29 10:32로 같다. 이어하기 때 다시 쓰여서 단계별 실제 소요 시간을 파일로는 알 수 없다. 9/24~9/28 사이 결과 파일도 없다.

## 4. 시연 전에 알아 둘 것

시연은 README의 시연 순서대로, 로컬 제공자로 한다. 다음 우회 동작을 시연 대본에 적는다.

- 정적 서버로 열 때는 SPA 폴백이 있어야 /j/코드 초대 링크가 열린다(npx serve -s).
- 웹에서 공유가 안 되면 복사로 대체된다.
- 합류는 기기 여러 대가 아니라 같은 기기의 "다른 사람으로 합류(시연)" 버튼으로 한다.
- 네트워크 끊김은 더보기의 시연 토글로만 들어간다. 와이파이를 꺼도 대기 표시가 뜨지 않는다.
- 여행 진행(19)에서 이미 떠난 스팟의 도착 취소와 잘못된 건너뜀은 고칠 수 없다(Q1). 조작을 틀리면 시연 리셋부터 다시 한다.
- 웹에서는 EXIF를 못 읽어 사진의 촬영 시각·위치 칩이 추정으로만 나온다.
- 프로필 이미지는 "압축 예정 크기" 표시만 있다. 실제로 줄지 않는다.
- 넷째 날부터 기록 지도 색이 겹친다(Q3). 경주 2박 3일 시나리오에서는 드러나지 않으니 다른 여행으로 즉석 시연하지 않는다.
