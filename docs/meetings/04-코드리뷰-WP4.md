세 리뷰어가 낸 지적은 35건이다(blocker 1, major 12, minor 22). 겹친 지적이 둘 있다. 구간 수단 LWW는 명세 S1과 정확성 C2가 같고, 복귀 구간 수단은 명세 S3와 정확성 C4가 같다. 그래서 서로 다른 문제는 33건이다. 반영 전에 WP4 파일을 모두 다시 읽었다. 파일 수정 시각이 모두 리뷰(09-26) 이전이라, 앞선 반영 시도가 남긴 변경은 없었다.

blocker 1건과 major 12건은 모두 반영했다. 그 가운데 2건(구간 수단 LWW, 복귀 구간 수단)은 공유 타입 types.ts에 필드가 있어야 제대로 끝난다. 그래서 WP4 파일 안에서 타입을 넓혀 동작을 먼저 맞추고, 타입을 정식으로 바꾸는 일은 FOUNDATION에 공유 변경 요청으로 넘겼다. minor는 22건 가운데 12건을 모두 반영했고(D16은 결정 기록), 5건은 WP4 쪽 몫만 반영했다. 4건은 src/ui·WP2 소유 파일을 고쳐야 해서 요청으로 넘겼다. 나머지 1건인 FR-603의 체류 줄이기 조정안(S7)은 팀 결정으로 그대로 둔다.

검증 결과는 이렇다. npx tsc --noEmit은 오류 0건이다(다른 패키지 파일 포함). npm test는 536개 가운데 530개 통과, 실패 0, todo 6(통합 골든)이다. wp4 테스트는 9개 파일 73개로, 개발 보고 때의 62개에서 늘었다. node scripts/gate-scope.mjs WP4는 통과했고, npx expo export --platform web --output-dir /tmp/yt-export-wp4도 성공했다.

명세 S1과 정확성 C2, 명세 S3과 정확성 C4는 같은 문제라 한 번씩만 고쳤다. 그래서 서로 다른 major는 10건이다.

세 리뷰어가 공통으로 확인한 것은 이렇다. 골든 수치, 선별 불변식, Held-Karp 정렬, 24시간 캐시, 구간 100 이하 예산, 순수 계층 분리(core·services·features의 .ts에 RN import 없음)는 맞다. 금지 스타일 위반도 없다. 조건으로 걸린 것은 세 가지다. 첫째, 12의 '이 구간만'이 재정렬로 사라지는 결함이다. 둘째, 편집 규칙(LWW, 수동 순서 보호 범위, 낡은 계획 기준 편집)이 어긋난다. 셋째, 09·10 헤더와 타임라인 축이 목업과 다르다.

## 4. 공유 변경 요청

1. src/types.ts (FOUNDATION): LegOverride에 `at?: number`(마지막 편집 시각)와 `cleared?: boolean`(해제 묘비)을 더한다. 지금은 ops/schedule.ts의 LegEntry가 같은 모양으로 넓혀 쓴다. 필드를 더한 뒤 LegEntry를 LegOverride 별칭으로 바꾸면 된다. trip.legs를 새로 읽는 코드는 liveLegs()로 묘비를 걸러야 한다.
2. src/types.ts (FOUNDATION): DayPlan에 `returnLeg?: { transport: Transport; estimated: boolean; notices: ItemNotice[] }`를 더한다. 지금은 core/planner/day.ts의 DayPlanWithReturn과 returnLegOf()가 넓혀 쓴다. 19 여행 진행(WP5)도 복귀 줄을 그리면 returnLegOf를 쓰면 된다.
3. src/ui/tokens.ts (src/ui 소유): T에 step(SemiBold 13.5/19), stepOn(Bold 13.5/19), note(Regular 11.5/19.5), noteStrong(Bold 11.5/19.5), nmSm(Bold 14/20) 변형을 더한다. T.time과 숫자 변형에 fontVariant ['tabular-nums']를 추가하고, TypeStyle이 fontVariant를 받게 한다(D5·D6·D8·D14).
4. src/ui/Notice.tsx WarnCard (src/ui 소유): 설명 문장은 c='warn'(행간 1.6)으로 쓴다. 조정안 행은 borderWidth 1, surfaceC.warnLine, R.btnSm으로 하고, 라벨은 SemiBold 12.5로 한다. 값은 Chip tone='warn'으로 바꾼다(D11).
5. src/store/trips.ts (WP2): recompute의 buildPlan deps에 `clock: appClock()`을 넣는다(D15). 그래야 08에 단계 시간이 나온다.

## 5. 남은 위험

- C5 보호 테스트는 예전 코드에서도 통과한다. 결함이 실제로 드러나는 것은 실키 카카오처럼 추정과 크게 다르고, 세 회차 안에 수렴하지 않는 경우다. 통합 때 실키 기록으로 다시 본다.
- 수동 순서가 더는 제외를 막지 않는다. 그래서 전에는 초과로 남던 날이 이제 자동 제외로 풀린다. 10 화면은 새로 제외된 스팟을 알리고, 되돌리기로 원래대로 돌릴 수 있다. 07 미리보기 문구(WP3)에 '순서를 바꾼 곳도 넘치면 빠진다'는 설명이 필요한지는 통합 때 본다.
- 개발 서버 금지 규칙 때문에 09·10·12 화면은 렌더를 직접 보지 못했다. 치수는 리뷰어 실측값을 코드에 옮겼고, 웹 export 빌드는 성공했다.
