## 2. 결정: 소셜 동일 이메일의 연결 대상

- 결정: 연결 대상은 모의 제공자가 돌려준 이메일(providerEmail)과 정확히 같은 이메일 계정이다. "이 기기에서 마지막으로 로그인한 계정" 방식은 버린다.
- 이유: 실제 소셜 로그인도 제공자가 돌려준 이메일로 기존 계정을 찾는다. 마지막 로그인 계정 방식은 시연하는 사람이 결과를 예측하기 어렵다.
- 반영: 26 화면에서 '같은 이메일'을 고르면 "카카오가 돌려줄 이메일(모의)" 입력칸이 나온다. socialFlow가 이 값을 providerEmail로 넘긴다. wp1-auth의 FR-103 테스트 3개를 이 방식에 맞게 고쳤다.
- 17 화면의 연결(intent 'link')은 지금 계정 id(linkToAccountId)에만 로그인 방법을 붙이고, 세션은 바꾸지 않는다. 결과 계정이 지금 계정과 다르면 flows가 거부한다(features/account/social.ts의 judgeSocial). 계약만 따르는 제공자가 새 계정을 돌려줘도 로그인한 사람이 바뀌지 않는다. 연결 모드에는 '같은 이메일' 선택지가 없다.
- 계약 요청: AuthProvider.social 입력에 linkToAccountId와 providerEmail을 정식으로 넣고, getAccount(accountId)를 추가해 달라고 FOUNDATION에 요청한다. 지금은 LocalAuthProvider 타입과 SocialInput으로 확장해 쓴다.
