## plan.json

설계 리뷰에서 확정한 계획 원문이다. 최상위 키는 다음과 같다.

- `decisions` — 확정 결정(확정 버튼 없음·자동 선별, 1단계 도보·자동차, 국내 전용·SDK 중립, 게스트 세션 등)
- `scope` — 범위와 범위 밖
- `dependencies` — 쓰는 패키지
- `foundation` — 기반 작업 범위와 계약(부록 A, 추가분 A11·A12 포함)
- `workPackages` — 작업 패키지 WP1~WP6의 파일, 수용 기준
- `designRules` — 디자인·용어 규칙
- `qa` — 테스트 대상 파일(testTargets), 시연 시나리오(demoScenario)
- `minutesPath` — 회의록 위치

결정을 바꿀 때는 회의록에 근거를 남기고 이 파일을 같이 고친다.

## FR-추적표.md

기능명세서의 FR 35개와 추가 행(게스트 승격, FR-504 대중교통 확장, 계정 탈퇴), 비기능 16행을 코드 파일과 테스트 이름에 연결한 표다. 개발 보고의 주장이 아니라 코드와 테스트 결과로 판정했다. 기반 작업이 처음 만들고, 통합 QA(명세 추적)와 릴리스 점검(05)이 다시 썼다. 부분으로 남은 행과 그 이유도 여기 있다.

## workflow-state/

단계마다 남긴 결과 파일(JSON)이다. 다음 단계의 입력이고, 사용량 한도로 끊겼을 때 이어하는 근거다. 사람이 읽을 요약은 회의록에 있고, 이 파일들은 그 원자료다.

| 파일 | 내용 |
| --- | --- |
| `foundation.json` | 기반 작업(F) 보고 |
| `WPn-build.json` | 작업 패키지 n의 개발 보고 |
| `WPn-review-spec.json` | 명세 준수 리뷰 지적 |
| `WPn-review-correct.json` | 정확성 리뷰 지적 |
| `WPn-review-design.json` | 디자인 충실도 리뷰 지적 |
| `WPn-fix.json` | 리뷰 반영 결과(넘긴 항목은 summary 본문에 있다. openIssues는 비어 있어도 "없음"이 아닐 수 있다) |
| `qa-integrate.json` | 통합 담당 결과(공유 변경 요청 반영, 계약 A12) |
| `qa-tests.json` | QA 로직 테스트 결과 |
| `qa-trace.json` | QA 명세 추적 결과(통합 전 코드 기준이라 final에서 다시 고쳤다) |
| `final.json` | 릴리스 점검 결과와 남은 문제(openIssues) |
| `retro-pm.json`, `retro-tech.json`, `retro-qa.json` | 회고 발언 준비(범위·일정, 아키텍처·기술 부채, 테스트 보장 범위와 수동 점검 목록) |
| `retro-minutes.json` | 회고 회의록 작성 완료 표시 |

주의할 점: 이어하기 때 파일이 다시 쓰여 수정 시각이 실제 완료 시각과 다를 수 있다(WPn-build와 리뷰 파일 15개가 같은 시각). 최신 수치는 가장 뒤 단계 파일(final.json, retro-*.json)을 기준으로 본다.
