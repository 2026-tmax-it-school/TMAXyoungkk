# 기능 테스트 오류 목록 (2026-10-24)

직접 조작해 본 결과를 모았다. 요청대로 **오류는 고치지 않고 목록만** 만들었다.

- 환경: 웹 8090(서버 연결, 폰 폭), 공개 터널로 두 번째 사용자(게스트) 합류까지 확인했다.
- 테스트 계정은 `hanbg191919+ft1@gmail.com`이다. 끝에 계정 탈퇴로 지웠다(다시 로그인 불가 확인).
- 심각도: 높음 = 핵심 기능이 틀리게 동작, 중간 = 흐름이 막히거나 혼란, 낮음 = 문구·다듬기.

## 높음

### B1. 자동차 경로가 없으면 도보로 계산한다(카카오 자동차 길찾기로 대체하지 않는다)
- 현상: 주 이동수단이 자동차인데 전주역에서 첫 스팟까지 4.6km가 "도보 67분 · 직선거리 추정"으로 나온다. 시간표 맨 위와 맨 아래(복귀), 구간 안내, 길찾기("자동차 경로 없음"), 지도 첫날 요약("이동 2시간 50분")이 모두 이 값을 쓴다. 지도의 첫 구간 선도 도로가 아닌 직선이다.
- 원인 단서: 서버 로그에 `중계 상류 실패(osrm-table / osrm-route): fetch failed`가 반복된다. 이 컴퓨터에서 `routing.openstreetmap.de`에 닿지 않는다. 같은 서버의 `/kakao/navi/directions`는 직접 호출하면 성공한다.
- 영향: OSRM 공개 서버가 막히거나 느리면 자동차 일정 전체가 틀린 시간으로 짜인다. 공개 링크에서도 같다.
- 확인 위치: 시간표, 지도, 길찾기, 구간 안내, 여행 진행.

### B2. 공개 링크에서 구글·카카오 로그인이 안 된다
- 현상: 로그인 화면에서 구글을 누르면 "구글 로그인을 지금은 쓸 수 없어요 / 허용하지 않은 돌아올 주소입니다. 서버 OAUTH_REDIRECT_URIS에 이 주소를 넣어야 합니다"가 뜬다.
- 원인: 서버가 허용한 돌아올 주소가 localhost와 옛 터널 주소뿐이다. 터널 주소는 켤 때마다 바뀐다. 구글·카카오 콘솔에도 새 주소를 등록해야 한다.
- 추가: 일반 사용자에게 서버 설정 이름(`OAUTH_REDIRECT_URIS`)이 그대로 보인다.

## 중간

### B3. 공개 링크에 팀원의 실제 커뮤니티 글이 그대로 보인다
- 커뮤니티 이야기 탭에 `대장최윤재`의 글 3개가 보인다. 제목·내용에 "자살" 같은 민감한 말과 사진이 있다.
- 이메일 가입은 실제 Gmail 발송이 켜져 있어, 누구나 아무 주소로 인증 메일을 보낼 수 있다(주소당 하루 5통, 기기당 10분 10통 제한만 있다).

### B4. 가입 인증이 끝난 직후 "나가시겠습니까?" 창이 뜬다
- 재현: 커뮤니티 글쓰기(게스트) > 로그인 > 회원가입 > 인증 코드 입력.
- 현상: "계정으로 바꿨어요" 안내와 함께 글쓰기 임시저장 창("저장하고 나가기 / 취소")이 가입 화면 위에 뜬다. 취소하면 가입 2단계 화면에 그대로 남는다.

### B5. 채팅에서 장소를 놓친다
- "풍남문 가자", "풍남문 갔다가 가맥집에서 맥주 한잔 하자"는 후보로 추출되지 않았다. 같은 장소가 AI 추천에는 "풍남문"으로 나온다.
- 같은 채팅에서 "덕진공원 가고 싶어", "전동성당 가고 싶다 그리고 남부시장"은 추출됐다.
- 보조: "남부시장"이 "전주남부시장 한옥마을야시장"으로 묶였다(이미 있던 후보에 제안자만 추가).

### B6. 초대 화면이 코드가 바뀌어도 이전 결과를 보여 준다
- 재현: 초대 화면을 틀린 코드(`ZZZZ-ZZZZ`)로 연 뒤, 같은 앱 안에서 올바른 코드(`N5SD-SRFX`)로 다시 연다.
- 현상: 주소는 바뀌는데 화면은 "초대 코드를 찾을 수 없습니다"에 머문다. 새로고침해야 풀린다.

### B7. 내보낸 멤버가 같은 링크로 다시 들어올 수 있고, 내보내진 쪽은 이유를 모른다
- 방장이 멤버를 내보낸 뒤에도 그 사람이 기존 초대 링크로 다시 합류 화면을 본다(링크를 새로 만들기 전까지).
- 내보내진 쪽은 멤버 화면이 "여행방을 찾을 수 없어요 / 지워졌거나 더 이상 볼 수 없는 화면이에요"로 바뀌기만 한다. 내보내졌다는 안내가 없다.

### B8. 방장이 아닌 멤버가 방장이 담은 후보를 지울 수 있다
- 친구(게스트 멤버)가 방장이 담은 "경기전" 상세에서 "후보에서 지우기"를 눌러 지웠고, 방장 화면에서도 사라졌다.
- 의도라면 안내가 필요하고, 아니라면 권한 확인이 필요하다.

### B9. 일반 계정의 프로필에 시연 버튼이 보인다
- 프로필 화면의 "예시 사진으로 시연"이 관리자가 아닌 계정에도 보인다(관리자 전용 정리에서 빠졌다).

### B10. 채팅이 너무 긴 글을 아무 말 없이 보내지 않는다
- 1200자를 입력하고 보내기를 누르면 아무 반응이 없고 입력창에 글이 남는다. 글자 수 표시와 안내가 없다.

## 낮음

- B11. 후보 "지도에서 선택": 지도를 한 번 탭하면 확인 없이 근처 가게(향원회관)가 후보로 바로 추가된다.
- B12. 내가 공유한 일정의 상세에 "다른 사람이 짠 일정이에요"라고 나온다.
- B13. 일기: 내용이 비었을 때 저장 버튼을 눌러도 안내가 없다. 여행 시작 전 날짜에도 일기를 쓸 수 있다.
- B14. 가입 2단계와 비밀번호 재설정 화면에 "모의 메일함 / 개발용 메일함이 닫혀 있거나…" 문구가 일반 사용자에게도 보인다.
- B15. 시간표 편집: 처음 한 번 "경기전 앞으로"를 눌렀을 때 다른 두 곳의 순서도 같이 바뀐 것을 한 번 봤다. 다시 해 보니 재현되지 않았다(확인 필요).
- B16. 채팅 빈 화면의 예시 문구가 늘 "불국사 가자, 황리단길에서 점심"이다. 전주 여행방에서도 같다.
- B17. 커뮤니티 글 삭제: 누르는 버튼은 "삭제"인데 확인 창 버튼은 "지우기"이다.
- B18. 앱 둘러보기를 끝까지 봐도 홈의 "처음이세요?" 카드가 남는다.
- B19. 채팅 위쪽에 "완산구 1명 · 덕진구 1명" 칩이 나온다. 무슨 뜻인지 설명이 없고, 멤버 위치 정보가 아니라면 의미 확인이 필요하다.
- B20. AI 추천에서 "역사" 성향을 고르면 막걸리 골목, 카페처럼 역사와 무관한 곳이 섞인다.
- B21. 계정 탈퇴가 비밀번호 확인 없이 된다.
- B22. 3일 여행인데 후보 7곳이 모두 첫날(약 9시간 39분)에 몰리고 둘째·셋째 날이 비어 있다.
- B23. 사진 추가: 눌러서 "고르는 중"이 된 뒤, 파일 창을 닫으면 버튼이 풀리는지는 자동화로 확인하지 못했다.

## 정상 동작을 확인한 것

- 게스트 시작(빈 닉네임 안내), 여행방 만들기(지역 검색, 날짜는 지난 날 선택 불가, 기점 검색, 자동 이름), 초대 링크 만들기·복사.
- 후보: 장소 검색 담기, 좋아요 켜기·끄기, 상세, 꼭 넣기·빼기·투표대로, 날짜 지정·지정 풀기, 고정·고정 풀기, 채팅에서 장소 추출·되돌리기, 중복 후보 묶기.
- 시간표: 날짜 탭, 빈 날 안내, 편집(순서 앞뒤, 되돌리기 여러 번, 자동 순서, 체류 늘리기, 도착 지정, 이동수단 바꾸기), 한 번만 보이는 대체 경고.
- 지도, 구간 안내, 길찾기 화면, 여행 진행(수동으로 도착 처리·끝내기), 일기 쓰기·공유 메뉴·커뮤니티로 보내기.
- 추천(AI) 뽑기, 후보로 담기, 공유 일정 올리기·좋아요·가져와서 새 여행방 만들기·공유 내리기.
- 계정: 이메일 가입·인증, 게스트에서 계정으로 바꾸기(여행방 유지), 로그아웃·다시 로그인(여행방 복원), 틀린 비밀번호 안내, 비밀번호 재설정(약한 비밀번호 안내, 옛 비밀번호 거부), 닉네임 중복 안내, 계정 탈퇴.
- 협업: 공개 링크로 두 번째 사용자가 합류, 채팅 실시간 반영, 시간표·편집 내용 동기화, 방장이 멤버 내보내기, 틀린 초대 코드 안내.
- 커뮤니티: 게스트는 좋아요·글쓰기가 로그인 안내로 막힘, 로그인 후 글쓰기·수정 화면·삭제·좋아요, 태그 필터.
- 앱 둘러보기: 여행방이 있을 때 11단계가 모두 비춰지고 끝까지 간다.
- 관리자 전용 시연 도구: 관리자에게만 보인다(멤버, 초대 수락, 일기 메뉴, 프로필 시연 도구).

## 수정 상태 (같은 날 이어서)

수정함(테스트 1420개, 작업 범위 검사 6개 통과, 아직 커밋 안 함):
- B1 부분: 카카오가 경로 없음(예: 106 교통 장애)을 주면 없다고 단정하지 않고 OSRM·로컬 대체로 한 번 더 묻는다(`src/services/routes/kakao.ts`). OSRM 공개 서버가 이 컴퓨터에서 안 닿는 문제는 그대로다.
- B2: 오류 문구에서 서버 설정 이름을 뺐다(`server/auth.mjs`, 서버 재시작 필요). 공개 주소에서 소셜 로그인이 안 되는 근본 문제는 그대로다.
- B4: 글쓰기 나가기 확인은 그 화면이 맨 위일 때만 묻는다.
- B6: 같은 초대 화면에서 코드가 바뀌면 새 코드로 다시 확인한다.
- B8: 후보 영구 삭제(`spot/delete`)는 방장과 그 후보를 담은 사람만 한다. 빼기(`spot/remove`)는 그대로 모두 가능하다.
- B9: 프로필의 "예시 사진으로 시연"은 관리자만 본다.
- B12, B14, B16, B18: 문구와 카드 정리(내 일정 안내 문구, 모의 메일함 문구, 채팅 예시를 전주 기준으로, 프로필에서 둘러보기를 시작해도 홈 안내 카드를 닫음).
- B13: 확인해 보니 빈 내용이면 저장 버튼이 꺼져 있다. 오류가 아니었다.
- B10: 보내기 거부 사유는 토스트로 나온다(재확인 필요). 입력 칸에 500자 제한 표시는 아직 없다.

남은 것: B3(커뮤니티의 실제 글, 데이터 판단 필요), B5(채팅 추출에서 "풍남문"), B7(내보낸 멤버 재합류·안내), B11, B15, B17, B19~B23.

추가 수정(같은 날): B5 채팅 추출에 성문 이름(풍남문, 남문·북문·동문·서문)과 성당·성곽 접미사를 더했다(`src/core/ops` 아님, `src/core/extract/text.ts`). B17 커뮤니티 글 삭제 확인 버튼을 "삭제"로 맞췄다. B7 재합류는 코어가 이미 막는다(`member/join` 검증에서 내보낸 같은 사람은 `duplicateId`)는 것을 코드로 확인했고 화면에서 눌러 보지는 못했다. 내보내진 쪽 안내와 합류 화면 미리보기 문구는 남았다. B10은 입력 칸에 글자 수가 항상 보이는 부작용 때문에 넣지 않았다. 테스트 1421개, 작업 범위 검사 6개 통과.
