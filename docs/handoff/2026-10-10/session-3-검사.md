# 세션 3 검사 (2026-10-10)

세션 2(다른 계정)가 끝낸 작업을 다시 검사하고, 독립 리뷰에서 나온 문제를 고쳤다.

## 검사 방법

- 세션 2 기록(`docs/handoff/2026-10-09/session-2-이어하기.md`)의 검사를 다시 돌렸다. 결과가 기록과 같았다. tsc 0, `npm test` 785개 중 784 통과·건너뜀 1, 게이트 WP1~WP6 통과, `export:web` 성공·ttf 4, `expo install --check` 최신. 키가 든 파일은 git 추적·미추적 어디에도 없다.
- 세션 2에서 독립 리뷰를 못 받은 부분에 리뷰 에이전트 3개를 붙였다. 셋 다 읽기만 했고 재현 스크립트로 확인했다.
  - 기능 3(실제 길 이동 시간)
  - 기능 5(시뮬레이터 길 따라가기)와 조정안 계산 중 멈춤
  - 세션 2의 작은 수정 8건
- 웹에서 직접 확인했다. 시나리오 채우기, 지도, 길찾기, 시뮬레이터 재생, 더보기 안내. SVG 기본 지도는 `EXPO_PUBLIC_MAP_PROVIDER=svg`로 따로 띄워 확인했다(`.claude/launch.json`의 `yeojeong-web-svg`).

## 리뷰에서 나온 문제와 처리

| 영역 | 문제 | 처리 |
| --- | --- | --- |
| 작은 수정 #6 | **(blocker)** 웹 SVG 지도의 누르기가 모두 죽었다. react-native-svg 15 웹 `prepare()`가 `onPress !== null`이면 `onClick`을 `props.onPress`(undefined)로 덮어쓴다. 핀, 묶음 확대, 지도에서 선택이 웹 기본 지도에서 안 됐다 | `MapCanvas.tsx`가 웹에서 `{ onClick, onPress: null }`을 준다. 웹에서 묶음 확대, 핀 → 스팟 상세, 지도에서 선택을 다시 확인했다. 테스트 `wp5-google-map` |
| 작은 수정 #1 | 서버가 카카오를 못 쓰면 경로 줄이 mock이 되어, 도로 경로가 켜져 있어도 '장소와 경로를 예시 데이터로'라고 했다. 앱 .env에 카카오 키가 남아도 '키는 서버에만'이라고 했다 | `ServiceStatus.road`, `appKeyInBundle`을 더했다. 테스트 `wp1-provider-notice` |
| 작은 수정 #5 | 일기 '이동 중에서', '날짜만 정한 사진에서' | '이동하며 사진 N장을 남겼다' 등. 테스트 `wp6-diary` |
| 작은 수정 #3 | '1 / 2 단계' 다음 화면에 '2 / 2'가 없다 | 여행방 만들기에서 넘어온 멤버 초대만 '2 / 2 단계'(`fromCreate`) |
| 기능 3 | **(major)** 서버에 카카오 키가 없으면(503 kakaoDisabled) 자동차 구간을 캐시하지 않아 재계산마다 약 152번 요청, 곧 서버 속도 제한 429 | kakaoDisabled면 5분(실제 시계) 카카오를 묻지 않고, 실제 대체 결과는 10분만 캐시. 시나리오 재계산 요청 0번. `wp4-kakao-off` |
| 기능 3 | **(major)** 경로 캐시에 버전·제공자 표시가 없어 예전 직선 추정이 24시간 남았다 | 캐시 v2 + 제공자 서명(도로 경로, 카카오 방식, 차 계수, 구간표 해시). `wp4-route-cache` |
| 기능 3 | **(major)** 계획기가 구간마다 table을 하나씩 물었다(100구간 = 요청 76번) | 출발지·수단별로 묶어 묻는다(최대 12곳), OSRM은 출발지 여럿을 한 요청에. 100구간이 요청 25번. `TravelMatrix.estimatedCells` 추가(FOUNDATION). `wp4-travel-batch` |
| 기능 3 | (minor) 본문 읽기가 시간 제한 밖, 지우는 중 캐시 되살아남, 같은 구간 동시 중복 요청, 대중교통 실패 캐시, 캐시 시계가 가상 시각, 정류장 좌표 대신 GPS 원값, `ROAD_SHAPE=false`가 켜짐으로 읽힘, 복귀 구간 수단·추정 표시 | 모두 고쳤다. `wp4-osm-cooldown`, `wp4-road-shape`, `wp4-replan`, `wp4-api-proxy`, `wp5-return-leg` |
| 기능 5 | (minor) 이동 중 예상 도착이 직선 비율이라 옆으로 크게 도는 구간에서 가짜 지연 조정안 | 길 모양이 있으면 길 위 진행으로 잰다(`core/live/legPath.ts`). 시뮬레이터에만 모양이 있다. 기기 진행은 아직 직선 비율 |
| 기능 5 | (minor) U턴 길에서 이어 만들기와 길찾기 진행률이 반대 차선으로 튄다 | 지난 진행 위치에서 가장 이른 후보를 고른다. 길찾기 화면도 같은 규칙. `wp5-road-progress`, `wp5-navigate-progress` |
| 기능 5·작은 수정 | (minor) 조정안 계산 중 멈춤이 사용자의 재생·멈춤을 덮었다. 시작 대기 중 로그아웃·여행방 삭제를 놓쳤다 | `run.calcPause`로 바꾸고, 대기 뒤 다시 확인한다. `wp5-proposal-pause`, `wp5-start-recheck` |

## 남은 문제 (코드)

세션 2 목록에서 2(더보기 안내), 5(묶음), 7(캐시 키), 8(이동 중 ETA, 시뮬레이터만)은 풀렸다. 남은 것:

1. 빈 시간 추천(FR-604)이 지금 GPS로 장소를 묻는다. 서버 경유면 카카오로 간다(WP5 결정 필요)
2. 시나리오 채우기가 서버에 카카오 키가 있으면 카카오 장소를 쓴다(시연 수치가 깨질 수 있음)
3. iOS 백그라운드 기록 중에도 동기화 폴링·재계산이 돈다(WP2)
4. 자동차 OSRM 계수 1.3은 가정이다
5. 기기 진행의 이동 중 ETA는 아직 직선 비율이다(시뮬레이터만 길 기준)
6. 앱 `.env`에 `EXPO_PUBLIC_API_URL`과 `EXPO_PUBLIC_KAKAO_REST_KEY`가 함께 있을 때 빌드 점검이 없다(더보기가 알리기만 함)
7. 카카오 일시 실패가 묶음 중간에 나면 그 묶음 전체가 대체(provisional)로 간다(드묾)
