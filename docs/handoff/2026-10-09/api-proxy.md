# 기능 2. 키 숨기는 서버 — 구현 보고(두 번 돌았다)
## 첫 구현
요약: 키 숨기는 중계를 동기화 서버에 붙였습니다(server/proxy.mjs, sync-server가 /kakao/…와 /osrm/… 요청을 넘깁니다). tsc 0건, npm test 실패 0건이고, 실제 카카오 키와 실제 서버로는 돌려 보지 않았습니다.
- 서버가 받는 경로: 카카오 키워드·카테고리 검색(/kakao/local/keyword, /kakao/local/category), 자동차 길찾기(/kakao/navi/directions), OSRM route·table(/osrm/routed-{foot,car}/{route,table}/v1/{foot,driving}/좌표). OSRM 주소는 osm.ts가 만드는 꼴과 같습니다.
- 카카오 키는 서버 변수 KAKAO_REST_KEY에서만 읽어 Authorization: KakaoAK 헤더로 붙입니다. 키가 없으면 카카오 경로는 503 {error:'kakaoDisabled', reason}입니다. 상류 응답에 키 글자가 섞이면 [숨김]으로 가리고, 앱이 보낸 헤더는 상류로 넘기지 않습니다.
- 열린 중계 막기: 경로·매개변수는 허용 목록만 받습니다(모르는 이름·같은 이름 두 번·범위 밖 값은 400, 모르는 경로 404, GET 아닌 요청 405, 요청 줄 4KB 넘으면 414). 좌표는 route 10개·table 50개까지입니다.
- 속도·시간: IP별 분당 300회(넘으면 429와 Retry-After), 상류 8초 넘으면 504, 상류에 닿지 못하면 502, 상류 실패 상태 코드는 그대로 전달합니다.
- 캐시: OSRM과 카카오 길찾기의 200 응답만 저장소 경로 캐시(PostgreSQL route_cache, 없으면 메모리)에 24시간 둡니다. 캐시 키는 상류 주소의 sha256이고, 장소 검색은 캐시하지 않습니다.
- 공정 사용: OSRM에는 동시에 2개까지만 보냅니다(공개 서버는 설정이 더 커도 2개). 기다리는 요청이 100개를 넘으면 503 busy이고, 같은 요청이 겹치면 상류에는 한 번만 묻습니다.
- 앱: EXPO_PUBLIC_API_URL을 새로 넣었습니다. 있으면 카카오 요청이 키·인증 헤더 없이 서버로 가고, 앱에 EXPO_PUBLIC_KAKAO_REST_KEY가 없어도 카카오 장소·자동차가 켜지며 도로 모양 기본 주소가 {API_URL}/osrm이 됩니다.
- 서버가 503이면 장소는 로컬 장소 사전, 자동차는 도로 모양·로컬 모델(구간표 우선)로 넘어갑니다. 다른 실패와 직접 호출은 전처럼 던집니다.
- 더보기 서비스 상태(describeServices)에 '서버 경유' 라벨과 via 필드('server'|'app')를 적습니다.
- 테스트 23개를 더했습니다(서버 16, 앱 7). 상류는 가짜 fetch이고 DB는 PGlite라 네트워크가 필요 없습니다. 변이 검사 8개(키 가리기·동시 요청 제한·속도 제한·모르는 매개변수·실패 캐시·앱 인증 헤더·503 대체·요청 합치기)를 넣었다 빼 봤고 모두 테스트가 잡았습니다.

doc_notes: [사용법]
- 서버: test/server/.env에 KAKAO_REST_KEY(카카오 REST 키, 서버에만 둠), OSRM_URL(비우면 https://routing.openstreetmap.de), OSRM_CONCURRENCY(기본 2), PROXY_RATE_PER_MIN(기본 300, 0이면 끔)을 넣고 npm run server를 실행합니다. 시작 로그에 '중계: 카카오 켜짐/꺼짐, OSRM host'가 나옵니다.
- 앱: test/.env에 EXPO_PUBLIC_API_URL=http://<이 컴퓨터 IP>:8787을 넣습니다(보통 EXPO_PUBLIC_SYNC_URL과 같은 주소). 서버를 쓰면 EXPO_PUBLIC_KAKAO_REST_KEY는 비웁니다. 앱은 그 키를 쓰지 않지만, 값이 있으면 번들에는 들어갑니다.
- http(s) 주소가 아닌 API_URL은 없는 것으로 봅니다.

[엔드포인트] 모두 GET, CORS 허용
- /kakao/local/keyword?query&x&y&radius&page&size&sort&category_group_code
- /kakao/local/category?category_group_code&x&y&radius(category_group_code·x·y·radius 필수)&page&size&sort
- /kakao/navi/directions?origin&destination&priority&summary
- /osrm/routed-foot/route/v1/foot/{경도,위도;…}, /osrm/routed-car/route/v1/driving/{…}
  - route 매개변수: overview·geometries·steps·alternatives
- /osrm/routed-{foot,car}/table/v1/{foot,driving}/{…}
  - table 매개변수: sources·destinations·annotations

[상태 코드]
- 400 badRequest(reason), 404, 405, 414, 429 rateLimited(Retry-After)
- 503 kakaoDisabled(서버 키 없음) 또는 busy(OSRM 대기열 100개 초과, Retry-After 1)
- 504 upstreamTimeout(8초), 502 upstreamFailed 또는 badUpstream(JSON 아님)
- 상류가 실패하면 그 상태 코드와 본문을 그대로 줍니다.
- 캐시 대상 응답에는 X-Cache: hit/miss가 붙습니다.

[결정]
- 카카오 키는 서버 환경 변수에서만 읽습니다. 앱 요청에는 키도 인증 헤더도 없습니다.
- 캐시는 OSRM과 카카오 길찾기의 200 응답만 24시간 둡니다(route_cache, 메모리 모드면 메모리). 장소 검색은 두지 않습니다.
- 캐시 키는 '{종류}:{상류 주소 sha256}'이라 좌표가 키에 드러나지 않습니다.
- 공개 OSRM에는 동시 2개까지만 보내고, 같은 요청은 합칩니다. OSRM 쿼리 값(;·,)은 주소 꼴 그대로 둡니다.
- 앱이 서버에서 503을 받으면:
  - 장소는 로컬 장소 사전으로 넘어갑니다(createKakaoPlaces fallback).
  - 자동차 행렬·경로는 도로 모양·로컬 모델로 넘어갑니다(구간표 우선).
- 직접 키(시연 한정) 모드는 전과 같습니다(503이어도 던짐).
- describeServices: places와 routes 라벨에 '· 서버 경유'가 붙고 note는 '서버에 카카오 키가 없으면 …'입니다. ServiceStatus.via는 'server'|'app'입니다.
- 도로 모양 주소의 우선순위: EXPO_PUBLIC_ROAD_SHAPE에 준 주소 → 없으면 API_URL의 /osrm → 없으면 공개 서버. 'off'면 직선입니다.

[FR-추적표 반영 후보]
- 비기능 '키는 서버에만'과 '경로 API 24시간 캐시'를 서버 중계가 충족합니다.
- '카카오 웹 CORS 미확인' 항목은 서버 경유로 우회됩니다. 서버가 CORS를 줍니다.

[한계]
- IP는 소켓 주소입니다. 역방향 프록시 뒤에서는 모든 요청이 한 IP로 셉니다(X-Forwarded-For는 믿지 않음).
- 메모리 모드의 경로 캐시는 하루 한 번 보관 정리 전까지 크기 상한이 없습니다.
- 실제 카카오 키와 공개 OSRM 실응답은 이번에 확인하지 않았습니다(가짜 상류로만 검증).
남은 문제: 더보기 화면 문구 고치기(WP1, 범위 밖): src/screens/MoreScreen.tsx의 카카오 안내가 서버 경유일 때도 '키가 앱에 들어가니 시연에만 쓰세요'라고 나옵니다. describeServices에 via:'server'|'app'을 넣어 두었으니 WP1이 이 값으로 문구를 나눠야 합니다. / 장소 팩토리에 apiUrl 옵션 넣기(WP3, 범위 밖): src/services/places/index.ts의 createPlaceProvider가 apiUrl을 받지 않아서, 서버 경유일 때는 registry가 places/kakao·places/local을 직접 조립합니다. WP3가 팩토리에 apiUrl 옵션을 넣으면 registry는 팩토리만 부르면 됩니다. / 현재 위치 결정 필요(WP5, 범위 밖): 빈 시간 추천(src/core/live/freetime.ts, store/live.ts)이 GPS 현재 좌표로 places.nearby를 부릅니다. 카카오 장소를 쓰면(직접 키 또는 서버 경유) 현재 위치가 서버를 거쳐 카카오로 갑니다. 서버는 저장·기록·캐시하지 않고 넘기기만 합니다. 직접 키 모드에서는 이전부터 있던 동작이지만 '현재 위치를 외부로 보내지 않는다' 규칙과 맞지 않습니다. 기준 좌표를 머무는 스팟 좌표로 바꾸는 등 결정이 필요합니다. / 구간표 우선 결정 미적용: '예시 구간표 우선' 결정이 카카오 자동차 행렬에는 아직 적용되지 않았습니다. 서버나 직접 키로 카카오가 켜지면 시나리오 구간도 카카오 값을 씁니다. 다음 기능(OSRM 실제 시간을 계획에 쓰기)에서 같이 정해야 합니다. 서버의 /osrm/.../table 중계는 준비되어 있고, 앱 matrix는 아직 외부에 묻지 않습니다. / 실환경 확인 안 함: 실제 카카오 키와 공개 OSRM 실응답, npm run server 실행, 앱에서 실제로 붙는지는 확인하지 않았습니다(서버·브라우저·expo를 띄우지 않는 규칙). OSRM이 퍼센트 인코딩된 쿼리를 받는지 걱정되어 OSRM 쿼리 값은 인코딩하지 않고 넘깁니다. / 역방향 프록시 뒤 배포 시: IP별 속도 제한이 모든 요청을 한 IP로 셉니다. 이때는 X-Forwarded-For를 믿을지 정하는 설정이 필요합니다. / 번들에 키가 남는 경우: 앱 .env에 EXPO_PUBLIC_KAKAO_REST_KEY 값이 남아 있으면 API_URL이 있어도 번들에 값이 들어갑니다. 앱은 그 키를 쓰지 않습니다. .env.example에 '서버를 쓰면 비워 둔다'고 적었고, 사람이 실제 .env를 확인해야 합니다.

## 다시 점검
요약: 한도에 걸리기 전(10:02~10:12)에 구현과 테스트는 이미 끝나 있었다. 이번에는 남은 것을 점검하고 게이트를 다시 돌렸고, proxy.mjs 머리 주석 두 곳만 고쳤다.
- 서버(test/server/proxy.mjs, 새 파일): 키 숨기는 중계다. 경로는 GET /kakao/local/keyword, /kakao/local/category, /kakao/navi/directions, /osrm/routed-{foot,car}/{route,table}/v1/{foot,driving}/{좌표}. 허용한 경로와 매개변수만 받는다. 모르는 매개변수, 같은 이름 두 번, 범위 밖 값은 400, 없는 경로는 404, GET이 아니면 405, 요청 줄이 4KB를 넘으면 414다. 좌표는 route 10개, table 50개까지 받는다. IP별 분당 300회(429와 Retry-After)를 넘으면 막는다. 상류 시간 초과(8초)는 504, 상류에 닿지 못하면 502, 상류 상태 코드와 본문은 그대로 넘긴다.
- 카카오 키는 서버 변수 KAKAO_REST_KEY에서만 읽어 Authorization: KakaoAK로 붙인다. 키가 없으면 카카오 경로는 503 kakaoDisabled와 이유를 준다. 응답에 키 글자가 섞이면 가린다. 앱이 보낸 헤더는 상류로 넘기지 않는다.
- OSRM과 카카오 길찾기의 200 응답은 저장소 routeCache(PostgreSQL route_cache 또는 메모리)에 24시간 둔다. 장소 검색은 캐시하지 않는다. 같은 요청이 동시에 오면 상류에는 한 번만 묻는다. OSRM 동시 요청은 OSRM_CONCURRENCY(기본 2)이고, 공개 서버에는 설정과 상관없이 2개까지다. 대기열이 100개를 넘으면 503 busy다.
- sync-server.mjs에 붙였다: /kakao·/osrm 경로를 중계로 넘기고, proxyOptionsFromEnv로 설정을 읽고, 시작할 때 로그를 남긴다. startSyncServer에 proxy 옵션을 더했다(false면 중계 경로도 404).
- 앱: config.ts에 API_URL(EXPO_PUBLIC_API_URL)을 더했다. API_URL이 있으면 KAKAO_REST_KEY는 비운다. kakaoHttp는 서버 경유일 때 키도 인증 헤더도 없이 KAKAO_PROXY_PATHS로 요청을 옮기고, 실패하면 KakaoHttpError(status)를 던진다. isKakaoUnavailable은 503일 때만 참이다.
- 503이면 대체로 넘어간다. 장소(places/kakao.ts의 fallback)는 search·nearby·at이 로컬 장소 사전으로, 자동차(routes/kakao.ts)는 행렬을 통째로 로컬 모델(구간표 우선)로, 경로는 도로 모양으로 넘긴다.
- osm.ts의 osmProxyBase로 도로 모양 기본 주소가 {API_URL}/osrm이 된다. 주소 꼴은 공개 서버와 같다.
- registry: API_URL이 있으면 장소와 경로가 서버를 거쳐 카카오를 쓴다. describeServices는 라벨에 '서버 경유', 설명에 '키는 서버에만', ServiceStatus에 via:'server'|'app'을 적는다. 도로 모양 출처는 서버, 지정 서버, 공개 서버 중 하나로 표시한다.
- 테스트는 23개를 더했다. wp2-proxy 16개는 가짜 상류 fetch, 가짜 시계, PGlite, 실제 HTTP 서버를 쓰고, wp4-api-proxy 7개는 fakeFetch를 쓴다. 네트워크와 데몬은 쓰지 않는다.
