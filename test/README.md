# Young Trip 프로토타입 (React Native / Expo)

그룹 채팅에서 나온 "가고 싶은 곳"을 여행 루트로 자동 변환하는 한국어 모바일 앱의 프로토타입이다.
범위의 유일한 기준은 `../여행계획-앱-기능명세서-v0.2.md`이고, 화면은 핑크 목업(`../여행계획-앱-핑크-캔버스.html`)과
`../HANDOFF.md`의 디자인 토큰을 따른다.

지금은 **통합 QA와 릴리스 점검이 끝난 상태**다(2026-09-29). 기반 작업(F)이 세운 계약(타입·포트·스토어·라우트·ui) 위에
작업 패키지 WP1~WP6이 화면과 기능을 채웠고, 통합 때 공유 파일 변경 요청(계약 A12)을 반영했다. 목업 01~14 화면과
계획이 더한 15~26 화면이 전부 실제 화면이다(01 스플래시는 부팅 화면, 24 동명 장소 선택은 시트라 라우트가 아니다).

2026-10 메인 책임(한동관) 작업으로 다음이 더해졌다(2026-10-09 기준).

- 바탕 지도는 카카오맵(JavaScript 키가 있을 때, 2026-10-10 결정), 구글 지도는 선택 대체, 경로 선은 OpenStreetMap 실제 길
- 동기화 서버를 PostgreSQL로 영속화(`server/db/`). `DATABASE_URL`이 없으면 전처럼 메모리
- 키 숨기는 서버(`server/proxy.mjs`). 앱은 `EXPO_PUBLIC_API_URL`만 알고 카카오 키는 서버에만 둔다
- 실제 길 기준 이동 시간. 계획 시간도 OSRM에서 받는다(시연 구간표가 우선, 자동차는 교통 보정 1.3배)
- 백그라운드 동선 기록 옵션(기본 꺼짐, 개발 빌드 전용), 날짜별 권한 거부 기록, 기록 지도 색 정리
- 여행 시뮬레이터 점이 지도에 그려진 길을 따라간다
- CI를 GitFlow 브랜치에 맞추고 실 PostgreSQL 잡(`db`)을 더했다
- 계정 서버(`server/auth.mjs`, 2026-10-10). 서버 주소(`EXPO_PUBLIC_API_URL` 또는 `EXPO_PUBLIC_SYNC_URL`)가 있으면 가입·로그인이
  서버로 간다(scrypt 비밀번호, 해시만 저장하는 30일 세션 토큰, IP·이메일 시도 제한). 없으면 전처럼 이 기기 모의 인증
- 로그인·회원가입 화면 개편(2026-10-10 시안): 가운데 제목, 아이디 또는 이메일(닉네임으로도 로그인), 계정찾기(비밀번호 재설정),
  카카오·구글 로그인 버튼. 계정 서버와 키가 있으면 실제 구글·카카오 OAuth(인가 코드 + PKCE, 서버가 코드를 바꾼다, 4-1절)

- FR별 구현 파일·확인 방법·남은 문제: [`../docs/FR-추적표.md`](../docs/FR-추적표.md)
- 계획·계약·확정 결정 전문: `../docs/plan.json`
- 회의록: `../docs/meetings/` (최종 결과는 `05-통합-QA.md`)

2026-10 기능은 타입 검사·테스트(가짜 fetch·PGlite)로만 확인했다. 실제 PostgreSQL, 실제 카카오 키, 공개 OSRM 실응답,
서버 중계와 앱 연결, 백그라운드 동선 기록(개발 빌드), 시뮬레이터 점이 실제 길을 따라가는 화면은 아직 눈으로 보지 않았다.
2026-10-10 웹에서 시나리오 채우기(4.9초, 경로 서버 요청 3번), 지도, 길찾기, 시뮬레이터 재생, 더보기 안내, SVG 기본 지도 누르기를
확인했다(JS 오류 0). 이 컴퓨터는 공개 OSRM에서 429를 받는 상태라 정상 응답 때의 첫 계산 시간은 아직 재지 못했다.
자세한 것은 `../docs/handoff/2026-10-10/session-3-검사.md`다.

웹 미리보기(`npm run web`)로 화면을 직접 확인했다(2026-09-29). 게스트 시작 → 시나리오 채우기 → 후보(14·11·3, 제외 이유 문장) → 10/18 시간표(09:25 불국사 · 11:07 석굴암 · 12:57 교촌마을 한정식) → 지도(클러스터, 제외 마커)까지 HANDOFF 시나리오와 같게 나온다. 되돌리기를 누르면 되돌린 곳이 고정되고 다른 후보가 이유와 함께 빠진다. 이 확인에서 여행방 카드와 제외 스팟 행의 버튼 중첩(웹에서 button 안의 button)을 찾아 고쳤다.

## 실행 방법

node 24와 npm이 필요하다. 키가 하나도 없어도 앱은 전부 로컬 모의 제공자로 돈다.

```bash
cd test
npm install
```

### 웹 미리보기

```bash
npm run web              # expo start --web, 기본 포트 8090(RN_PORT로 바꾼다)
```

브라우저에서 `http://localhost:8090`을 연다. 목업 기준 폭은 390×844이므로 개발자 도구의 기기 모드에서
390×844로 맞춰 보면 목업과 비교하기 쉽다. 지도 키가 없으면 지도는 react-native-svg 기본 지도라 키 없이 보인다.
카카오 JavaScript 키를 넣으면 같은 자리에 카카오맵이 뜬다(아래 '실제 제공자로 바꾸는 방법' 2-0). 구글 지도는 2-1(선택).

웹에서 알아 둘 것:

- 위치(expo-location)는 보안 출처(HTTPS 또는 localhost)에서만 된다. 같은 와이파이의 다른 기기에서 `http://<내 IP>:8090`으로
  열면 위치 권한이 막히므로 여행 시뮬레이터를 쓴다.
- 공유 시트가 없는 브라우저에서는 초대 링크와 일기를 클립보드 복사로 대신한다.
- 웹에서 고른 사진은 EXIF와 파일 크기를 받지 못해 촬영 시각·위치를 추정하고, 이 세션에서만 보인다.

### 휴대폰에서 보기 (Expo Go)

```bash
npm start                # expo start, 포트 8090
npm run start:tunnel     # 같은 와이파이가 아니면 터널
```

터미널의 QR을 Expo Go로 찍는다. 네이티브 빌드와 실기기 동작은 아직 확인하지 못했다.

### 정적 웹 번들로 보기

```bash
npx expo export --platform web --output-dir /tmp/yt-export
npx serve -s /tmp/yt-export -l 8090    # 예: SPA 폴백(-s)이 있는 아무 정적 서버
```

초대 딥링크 `/j/코드` 경로는 SPA 폴백(모든 경로 → index.html)이 있어야 열린다. 폴백이 없으면 루트로 들어가
온보딩의 '초대 코드로 합류'나 초대 수락 화면의 코드 입력 칸을 쓴다.

### 서버 없이 검증

개발 서버를 띄우지 않고 아래 세 가지로 확인한다. CI(`../.github/workflows/ci.yml`)의 `check` 잡이 같은 세 단계와 ttf 4개 검사를 돈다.
`db` 잡은 postgres:17-alpine을 띄워 `tests/wp2-*.test.ts`를 실 PostgreSQL로 돌리고, 실 DB 묶음이 건너뛰거나 빠지면 실패한다.
트리거는 main·develop·feature/**·release/**·hotfix/** push와 main·develop PR이다. 로컬 재현은 `../CONTRIBUTING.md`의 'Reproduce locally'다.

```bash
npx tsc --noEmit                                            # 타입 검사(tests 포함)
npm test                                                    # node --test (tests/**/*.test.ts)
npx expo export --platform web --output-dir /tmp/yt-export  # 웹 정적 번들
```

작업 패키지는 자기 범위만 보는 게이트를 쓴다.

```bash
node scripts/gate-scope.mjs WP3   # tsc 중 WP3 파일 오류 0, tests/wp3-*.test.ts, YT_SCOPE=WP3 foundation 테스트
```

## 여행 시뮬레이터 사용법

2·3차 실시간 기능(현재 위치, 도착 감지, 지연 조정안, 빈 시간 추천, 사진, 이동 경로 기록)은 경주를 실제로 돌아다닐 수 없어서
시각을 빠르게 돌리는 여행 시뮬레이터로 시연한다. 시뮬레이터로 재생하는 동안에는 화면 위에
'여행 시뮬레이터로 재생 중 · 실제 위치 아님' 띠가 붙는다.

1. 여행방을 고른다. 빠르게 하려면 더보기 → 시연 도구 → **시나리오 채우기**('대화 전부')로 경주 2박 3일 여행방을 만든다.
2. 여행 진행 화면을 연다. 더보기 → **여행 진행 · 시뮬레이터**, 또는 지도 탭의 '여행 진행' 버튼이다.
   계산된 시간표가 없으면 '루트 계산'으로 먼저 계산한다.
3. 위쪽 날짜 칸에서 날짜를 고른다(재생 전에만 바꿀 수 있다). 시연 기준 날짜는 10/18이다.
4. 시뮬레이터 칸에서 **프리셋**을 고른다.

   | 프리셋 | 일어나는 일 | 기능 |
   | --- | --- | --- |
   | 정상 | 시간표대로 움직이고 스팟마다 도착이 기록된다 | FR-601·602 |
   | 지연 25분 | 첫 스팟에서 25분 더 머문다. 다음 스팟 조정안이 나온다 | FR-603 |
   | 영업 종료 | 마감이 가장 가까운 스팟 앞에서 오래 머문다. 도착 예정이 마감을 넘기면 그 스팟 빼기가 조정안 1순위다 | FR-603 |
   | GPS 음영 | 두 번째 스팟 가는 길에 정확도가 떨어진다. 음영 안내가 나오고 판정에서 빠진다 | FR-601·602 |
   | 지나침 | 첫 스팟을 머물지 않고 지나친다. 다음 스팟에 도착하면 첫 스팟은 건너뜀이다 | FR-602 |
   | 옆 건물 | 첫 스팟 120m 옆 건물에서 5분 머문다. 옆 건물은 도착이 아니다 | FR-602 |
   | 권한 거부 | 위치 권한이 없다. 수동 진행 모드에서 '도착 처리' 버튼으로 진행한다 | FR-601 |
   | 빈 시간 | 첫 스팟을 30분 만에 나선다. 남는 시간에 도보 800m 안의 주변 2~3곳을 추천한다 | FR-604 |
   | 10/18 종합 | 불국사 도착, 석굴암 구간 지연 조정안, 점심 뒤 빈 시간 추천, 사진 이벤트가 이어진다 | FR-601~604·701 |

5. **여행 시뮬레이터로 재생**을 누른다. 배속은 1배·10배·60배·300배이고, 일시정지와 재생을 오갈 수 있다.
   시연은 60배가 알맞다.
6. **시각 점프**로 기다리지 않고 넘어간다. '다음 스팟 10분 전'과 '여행 종료 뒤'(경주 시나리오는 10/20 10:00) 두 가지다.
   종료 뒤로 점프하면 홈에서 완료 상태가 되고, 일정·후보 편집이 잠긴다(사진·일기는 계속 된다).
7. 조정안 시트가 뜨면 **적용** 또는 **원래대로**를 고른다. 지연을 잡은 순간부터 고를 때까지 재생이 멈춘다(조정안을 계산하는 동안에도
   멈춘다. 계산이 경로 서버를 기다리는 사이 시각이 흐르면 지난 상황을 묻게 된다). 계산 중에 재생·멈춤을 누르거나 앱이 화면 밖으로
   가면 그 상태를 따른다. 프리셋을 바꿔 다시 시작하면 멈춘 채로 시작하지 않는다. 같은 상황의 조정안은 30분에 한 번만 뜬다.
8. 도착한 스팟에는 '도착 취소'가 있다. 권한 거부나 수동 진행에서는 '도착 처리'로 직접 도착을 남긴다.
9. 끝나면 '여행 진행 끝내기'를 누르고, 같은 화면의 '기록 지도'·'사진' 버튼으로 기록을 본다.

알아 둘 것:

- 시뮬레이터가 켜지면 가상 시각이 앱 시계가 된다. 멈추거나 끝내도 가상 시각은 남고, 더보기 → 시연 도구 → **시연 리셋**만
  실제 시각으로 되돌린다.
- 가상 시각이 켜져 있으면 '기기 위치로 시작'은 막힌다. 실제 위치와 가상 시각이 섞이지 않게 하려는 것이다.
- 시작하며 기다리는 동안(일정 계산, 구간 모양 최대 1.5초, 위치 권한) 로그아웃·여행방 삭제·나가기가 있으면 시뮬레이터 시계나
  방문 기록을 바꾸기 전에 시작을 멈춘다.
- 앱이 화면 밖으로 나가면 시뮬레이터는 위치 확인과 재생을 멈추고, 그 사이 경로는 채우지 않는다.
- 위치 갱신은 30초 간격이고 20m 안에서 멈춰 있으면 기록하지 않는다. 도착은 정확도 50m 이하 샘플이 반경 100m 안에 3분 머물 때다.
- 시뮬레이터 점은 지도에 그려진 길(OpenStreetMap·카카오 도로 모양)을 따라간다(`src/core/sim/track.ts`, `legShapes.ts`).
  시작할 때 그날 구간 모양을 최대 1.5초 기다리고, 못 받은 구간은 직선으로 시작했다가 받는 대로 같은 시각표로 다시 만든다.
  조정안 적용 뒤 이어서 만들 때는 지금 위치가 길에서 150m 안이면 남은 길을 따라간다. 시각·이벤트·도착 판정은 직선일 때와 같다.
  길에 붙일 때는 가장 가까운 지점에서 20m 안인 후보 가운데 가장 앞을 고르고, 직전 진행을 알면 그보다 50m 넘게 뒤인 후보는
  건너뛴다(`src/core/live/legPath.ts`). 그래서 U턴 길에서 반대 차선으로 튀지 않는다. 길찾기 진행률도 같은 규칙이고 구간마다 지난 진행을 이어 쓴다.
  지연 계산(이동 중 예상 도착)은 그 구간 길 모양(지도 선과 같은 모양)을 알고 지금 위치가 길에서 150m 안이면
  예정 이동 시간 × (1 − 길 위 진행 비율)로 잰다. 모르거나 멀면 남은 직선거리 비율이다. 길 모양은 시뮬레이터 진행에만 넣으므로
  기기·수동 진행은 아직 직선 비율이다.

### 백그라운드 동선 기록 (기기 위치, 개발 빌드)

기기 위치로 오늘 날짜를 진행할 때 앱이 화면 밖에 있어도 동선과 스팟 도착을 남기는 옵션이다. 기본은 꺼짐이다.

1. 더보기에서 '기기 위치 사용'을 켠다. 여행 진행 화면에 '백그라운드 동선 기록' 줄이 생긴다.
2. 줄을 켜면 앱 사용 중 허용 → 항상 허용 → 알림(안드로이드 13 이상) 순으로 묻는다. 알림을 거부해도 기록은 켜진다.
3. 웹·Expo Go·작업 관리자가 없는 빌드에서는 켤 수 없고 이유('개발 빌드 필요')를 보여 준다.
   개발 빌드는 `npx expo run:ios`·`npx expo run:android`(이전 `ios`·`android` 폴더가 있으면 `npx expo prebuild --clean` 먼저)다.

- 화면 밖 샘플은 위치 로그와 도착 기록까지만 간다. 도착 알림, 지연 조정안, 빈 시간 추천은 앱으로 돌아와야 나온다.
- 오늘 날짜만 기록하고 자정이 지나면 멈춘다. 앱을 닫으면 기록도 끝난다.
- 위치는 서버로 보내지 않는다. 동선은 이 기기에만 남고(90일), 방문 기록(op)에는 좌표가 없다.
- 위치를 쓰려다 권한이 없어 수동 진행이 된 날은 그 날짜에 기록한다. 기록 지도는 그 기록을 읽고 '도착 지점만 이었다'고 안내한다.

## 지도 · 내 위치 버튼

11 지도 탭과 27 길찾기 지도의 오른쪽 아래에 둥근 '내 위치' 버튼이 있다(카카오맵·구글 지도 앱과 같은 자리). 미리보기 지도(스팟 상세 등)에는 없다.

- 한 번 누르면 위치를 찾고(도는 표시), 찾으면 지도가 내 자리로 옮겨 거리 단위로 당긴다. 파랑 점과 정확도 원이 걸을 때마다 움직인다.
- 한 번 더 누르면 따라가기(버튼이 파랑): 걷는 동안 지도가 나를 따라온다(5m 안쪽 흔들림은 무시, 1초에 한 번까지). 루트 전체로 다시 맞추지 않는다.
- 따라가기 중 지도를 끌거나 확대하면 따라가기만 풀린다. 또 누르면 끈다(위치 감시도 끔). '전체 보기'는 루트 전체로 돌아간다.
- 위치는 버튼을 눌렀을 때만 읽는다. 화면을 떠나거나 앱이 뒤로 가면 끈다. 여행 진행 중(시뮬레이터 포함)이면 GPS를 따로 켜지 않고 진행 위치를 쓴다.
- 권한: 처음 누를 때 위치 권한을 묻는다. 거부하면 켜는 방법을 토스트로 알린다(웹은 주소창 왼쪽 사이트 설정, 앱은 휴대폰 설정).
  12초 안에 위치가 안 오면 '받지 못했어요'로 알리고 꺼진다.
- 웹은 브라우저 위치(navigator.geolocation)를 쓰고 **https 주소나 localhost에서만** 된다. 같은 와이파이의 `http://<내 IP>:8090`에서는
  '이 주소에서는 위치를 쓸 수 없어요'라고 알린다.
- 좌표는 기기 안에서만 쓴다. 서버로 보내거나 저장하지 않고, 길찾기의 출발·도착도 바꾸지 않는다. 지도 SDK가 받는 타일 범위만큼만
  보는 곳이 드러난다(손으로 지도를 옮길 때와 같다). 규칙은 `src/core/map/locate.ts`, 위치 공급은 `src/components/map/useMyLocation.ts`.

## 길찾기

길찾기는 두 가지다.

| 화면 | 여는 곳 | 하는 일 |
| --- | --- | --- |
| 27 길찾기(자유 길찾기) | 지도 탭 위 칩 '길찾기'(여행방이 없으면 머리줄 아이콘), 스팟 상세 '여기까지 길찾기' | 아무 두 지점을 골라 자동차·대중교통·도보를 견준다. 카카오맵 앱 길찾기와 같은 흐름 |
| 13 길찾기 · 구간 내비 | 지도 탭 시트 '구간 안내', 여행 진행 | 계획 구간(스팟 → 다음 스팟)만 안내한다. 그대로 둔다 |

27 자유 길찾기(`src/screens/DirectionsScreen.tsx`, 규칙은 `src/core/map/directions.ts`):

- 출발·도착 줄을 누르면 고르기 시트가 열린다. 장소 검색(두 글자 이상, 잠깐 멈추면 찾고 엔터는 바로), 내 위치, 지도에서 고르기,
  여행방 기점, 여행방 스팟 중 하나를 고른다. 지도에서 고르면 누른 곳 150m 안 장소 이름을, 없으면 '지도에서 고른 곳'을 쓴다.
  오른쪽 버튼으로 출발과 도착을 바꾼다.
- 출발 기본값은 그날 기점이다. 여행방이 없으면 두 칸이 비어 있고 검색·지도 선택만 쓴다(검색 지역은 반대쪽 끝점이 든 지역, 없으면 첫 지역).
- 두 끝이 정해져야 경로를 묻는다. 세 수단을 한꺼번에 묻고(`routes.route`), 끝점이 바뀌면 앞 응답은 버린다. 경로가 없으면 '경로 없음'이다.
- 수단 줄은 시간·거리, 가장 빠름 칩, '시간 추정'(실제 길 모양) · '직선거리 추정' 칩, OpenStreetMap 출처 칩을 단다.
  대중교통은 모의 모델이라 늘 추정이고 모델 안내 문구를 보인다. 안내 줄이 없는 결과는 방위·거리 한 줄과 도착 줄을 만든다.
- '카카오맵으로 열기'는 `https://map.kakao.com/link/from/이름,위도,경도/to/이름,위도,경도`(이름은 URL 인코딩)를 연다.
  '안내 시작'은 여행 진행 중일 때만 보이고 여행 진행 화면으로 간다.
- 위치: 위치는 서버로 올리지 않는다는 원칙의 유일한 예외다. 사용자가 '내 위치'를 직접 고른 길찾기만 그 좌표를 경로 서버로 보내고
  (사용자가 '카카오맵으로 열기'를 누르면 그 링크에도 담긴다), 그때 화면에 한 줄로 알린다. 반대쪽 끝이 내 위치일 때 장소 검색 기준점은
  내 위치 대신 지역 중심을 쓴다. 내 위치를 누른 뒤 시트를 닫으면 늦게 온 위치는 버린다. 여행 진행 중이면 진행 위치를, 아니면 그때 한 번만 읽는다(`src/services/location/once.ts`). 권한이 없거나
  위치를 받지 못하면 안내 문구를 보이고 다른 방법으로 고르게 한다.

## 시연 순서

시나리오 데이터는 HANDOFF와 같다. 경주 2박 3일(10/17~10/19), 자동차, 멤버 민지(방장)·준호·수아·지우(나중 합류),
기점 라한셀렉트 경주. 채팅 13줄에서 후보 14곳이 나오고 확정 11곳, 제외 3곳(동궁과 월지, 감은사지 삼층석탑, 대릉원 돌담길)이 된다.

### 빠른 시연 (5분)

1. 더보기 → 시연 도구 → 시연 리셋 → 온보딩에서 닉네임 '민지'로 **게스트로 시작하기**(30일·기기 한정 안내).
2. 더보기 → 시연 도구 → 시나리오 채우기 '대화 전부'. 진행 막대가 끝나면 경주 여행방이 생긴다.
3. 후보 탭: 후보 14 · 확정 11 · 제외 3과 제외 사유. 확정 버튼은 없다. 제외 카드에서 동궁과 월지를 되돌리면 고정되고
   다른 스팟이 이유와 함께 빠진다.
4. 시간표 탭 10/18: 09:00 출발 → 09:25 불국사 → 11:07 석굴암 → 12:57 교촌마을 한정식.
5. 지도 탭: 날짜별 선 색(잉크·청회색·초록), 순번 핀, 제외 흰 핀, 숫자 원(클러스터). 핀을 누르면 스팟 상세.
6. 여행 진행 · 시뮬레이터: 10/18, 프리셋 '10/18 종합', 60배 재생 → 도착, 지연 조정안 적용, 빈 시간 추천.
7. 더보기 → 사진 → 일기 → 기록 지도.

### 전체 시연 (계획 qa.demoScenario 28단계를 화면 이름으로 옮긴 것)

1. 앱 실행 → 스플래시가 폰트 4개·저장소 4개 복원을 단계 진행률로 보여준다.
2. 더보기 → 시연 도구 → 시연 리셋.
3. 온보딩: '민지'로 게스트로 시작하기. 30일·기기 한정·복구 불가 안내(FR-105).
4. 홈 빈 상태 → 여행방 만들기(FR-203 예외).
5. 여행방 만들기 3단계: 경주, 10/17~10/19, 자동차. 기점 검색에 '없는곳' → 결과 없음과 '기점 없이 만들기'를 본 뒤
   라한셀렉트 경주를 고른다. 종료일을 늘려 15일 확인 창을 보고 되돌린다(FR-201, 205, 504).
6. 더보기 → 여행방 설정 · 날짜별 기점: 10/17 활동시간, 10/18 직전과 같음, 10/19 복귀 없음, 보관 기한(FR-205, 데이터 보존).
7. 개인 모드라 채팅 입력이 막힌 것을 본다. 후보 탭 수동 등록: '황남빵'은 동명 선택 시트, '호미곶'은 목적지 밖 확인,
   없는 이름은 결과 없음(FR-202).
8. 더보기 → 멤버 · 초대 링크: 초대 링크 만들기, 복사, 공유(웹은 복사로 대체), 만료일과 남은 자리(FR-301).
9. 멤버 화면 '이 기기에서 다른 사람으로 합류해 보기(시연)' → 초대 수락 화면에서 준호·수아로 합류 → 그룹방 전환과 채팅 활성.
   같은 코드로 다시 열면 '이미 참여'. 코드 없이 열면 코드 입력 칸(FR-302).
10. 그룹 채팅: 채팅 메뉴 → '시나리오 1~11줄 재생' → 말풍선 강조와 추출 카드, 되돌리기. 수아로 교촌마을 한정식 고정·10/18 지정
    (FR-304, 401, 402).
11. 지우가 초대 수락으로 게스트 합류 → 채팅 메뉴의 뒤쪽 줄 재생으로 '동궁과 월지 야경 유명하대'.
12. 더보기 → 시연 도구 → 네트워크 끊김 → 메시지 '전송 대기' → 다시 연결 → 순서대로 전송과 밀린 재계산(FR-304 예외).
13. 루트 계산 화면: 실제 단계와 단계 시간, 경로 조회 건수, 선별 규칙 전문(FR-505, 501).
14. 후보 탭: 14 · 11 · 3과 제외 이유. 동궁과 월지를 되돌려 고정하면 다른 스팟이 이유와 함께 빠진다(FR-402, 403).
15. 불국사 스팟 상세: 제안자 3명, 채팅 원문, 체류를 늘리면 무엇이 빠지는지 예고(FR-803).
16. 시간표 탭 10/18 타임라인(FR-502).
17. 일정 편집: 순서 이동, 체류 ±15분, 도착 시각 조절 → 수용량 초과 경고와 조정안 적용. 고정을 바꿔도 순서가 남는다(FR-503).
18. 지도 탭: 순번 핀, 날짜별 색, 제외 흰 핀, 클러스터 확대, 핀 → 상세(FR-801, 802, 803).
19. 시간표 이동 줄 → 이동수단 · 경로 비교: 불국사→석굴암 자동차·도보·대중교통(2차 배지)과 '이 구간만'.
    감은사지는 대중교통 경로 없음 대체 안내(FR-504).
20. 프로필 · 성향 태그 → 여행지 추천 3~5곳과 추천 이유(FR-104, 404).
21. 여행 진행 · 시뮬레이터: 10/18 종합 60배 → 현재 위치, 불국사 도착, 석굴암 구간 지연 조정안 적용·원래대로, 빈 시간 추천,
    사진 이벤트. 권한 거부 프리셋은 수동 진행 모드(FR-601~604, 701).
22. 길찾기: 구간 안내와 시뮬레이터 띠.
23. 시각 점프 '10/20 여행 종료 뒤' → 완료 상태와 편집 잠금.
24. 사진(EXIF·추정 칩, '모의 사진 3장 올리기(시연)') → 일기 자동 생성·여러 줄 편집·공유 → 기록 지도의 실제 이동 점, 계획 선,
    기록 없는 구간 점선(FR-701~704, 804).
25. 계정: 회원가입으로 승격 → 모의 메일함 '인증하기'·재발송 → 로그인 5회 실패 10분 잠금(기기 토큰 가정 문구) →
    카카오 모의 동의에서 같은 이메일 연동 확인 → 프로필 닉네임 중복·이미지 압축 표시 → 게스트 승격(FR-101~104).
26. 권한: 준호로 전환해 나가기, 방장 삭제 확인 1회, 방장 나가기는 위임 미결정 안내(FR-204). 수아 내보내기, 방장 본인 불가,
    전원 나가면 개인 모드(FR-303).
27. 계정 탈퇴: 승격한 사용자가 프로필에서 계정 탈퇴 → 그 사람 사진은 사라지고 채팅·제안은 '탈퇴한 멤버'로 남는다(데이터 보존).
28. 시연 리셋 뒤 처음부터 다시 돌려 같은 숫자(14 · 11 · 3, 10/18 시각)를 재현한다.

## 프로토타입이라 다른 점

실서비스와 다른 부분이다. 명세를 되돌린 것은 없고, 명세가 정하지 않은 것은 되돌릴 수 있는 최소 동작으로 두었다.

- **서버는 선택이다.** 상태는 기기에 저장한다(`young-trip/ui`, `young-trip/session`, `young-trip/trips`, `young-trip/live`, v2).
  그룹 동기화 기본값은 이 기기 안 루프백이라, 여러 사람은 같은 기기에서 '다른 사람으로 합류(시연)'과 보내는 사람 전환으로 보여준다.
  이 두 기능은 시연 전용이다. 기기 간 동기화는 `npm run server`(메모리 또는 PostgreSQL)로 되지만 기기 간으로는 아직 확인하지 못했다.
  서버에는 인증이 없다. 여행방 ID를 아는 사람은 op를 읽고 쓸 수 있다(실서비스 전 결정 필요).
- **계정은 서버가 없으면 모의 인증이다.** 인증 메일은 앱 안 모의 메일함으로 오고, 소셜 로그인은 모의 동의 화면에서 제공자 이메일을 직접 넣는다.
  모의 인증 비밀번호는 salt + SHA-256 한 번(느린 해시 아님)이고, 시도 제한은 IP 대신 기기 토큰으로 센다.
  서버 주소가 있으면 계정 서버(4절)를 쓴다. 그래도 메일은 보내지 않는다(개발 서버 보낸편지함을 모의 메일함으로 보여 준다).
  소셜은 서버에 구글·카카오 키를 넣으면 실제 OAuth(4-1절)이고, 키가 없으면 버튼이 그 이유를 알리고 모의 동의 화면으로 이어 간다.
  보낸편지함과 모의 소셜은 서버에 `AUTH_DEV_OUTBOX=1`(또는 `SYNC_ALLOW_RESET=1`)을 켰을 때만 열린다. 끄면 이메일 인증·재설정·같은 이메일 연결 확인을
  마칠 수 없고(메일을 볼 곳이 없다) 모의 소셜 로그인은 실패한다.
  게스트 승격의 userId 가로채기는 기기 토큰 확인으로 막지만, 아직 아무도 가입하지 않은 게스트 userId를 남이 먼저 쓰면 1일(인증 기한) 동안 막힌다
  (게스트를 서버에 등록하지 않아서다. 서버가 발급하는 게스트 비밀값이 남은 일).
  세션 토큰은 expo-secure-store 없이 앱 저장소(AsyncStorage, 웹은 localStorage)에 암호화하지 않고 둔다.
  비밀번호 재설정은 서버·제공자·흐름 함수까지 있고 화면은 아직 없다.
- **바탕 지도는 카카오맵(JavaScript 키가 있을 때)이 기본이고 구글 지도는 선택 대체다.** 키가 없거나 불러오지 못하면
  배경 타일 없는 기본 지도(SVG 격자)다. 카카오맵은 바탕 색 스타일을 바꿀 수 없어 무채색 목업과 바탕이 다르다.
  구글은 바탕 지도로만 쓴다. 구글 길찾기가 국내 도보·자동차 경로를 주지 않아 경로 선은 OpenStreetMap 길 모양(기본) 또는 카카오다.
- **장소는 예시 데이터, 경로 시간은 실제 길과 예시 구간표를 섞는다.** 카카오가 없으면 장소는 로컬 장소 사전(경주 중심)이다.
  도로 경로 서버(`EXPO_PUBLIC_ROAD_SHAPE`, 기본 켜짐)가 켜져 있으면 도보·자동차 시간과 선 모양·거리·안내 줄을 OpenStreetMap
  공개 경로 서버에서 받는다(키 불필요, 시연 한정). 시연 경주 구간표에 있는 구간은 구간표 시간이 우선이다(시연 수치 유지).
  자동차 OSRM 시간에는 교통 보정 1.3배를 곱한다(근거 자료 없는 프로토타입 가정, 카카오 실측과 견줘 고칠 값).
  경로 서버를 끄거나 실패하면 직선거리 추정이고 화면에 '추정' 칩이 붙는다. 대중교통은 모의 모델이다.
- **대화 인식은 규칙 기반이다.** 장소 사전 밖 장소(예: 기림사, 골굴사)는 찾지 못한다.
- **실시간 기능은 시뮬레이터로 시연한다.** 백그라운드 동선 기록은 옵션(기본 꺼짐, 개발 빌드 전용)이고 푸시 알림은 없다.
  알림은 앱 안 토스트와 시트다.
- **네트워크 끊김을 감지하지 않는다.** 오프라인은 시연 도구의 네트워크 토글로만 들어가고, 앱을 다시 열면 연결 상태로 돌아온다.
- **압축은 판정과 표시만 한다.** 프로필 이미지 5MB, 여행 사진 10MB 초과는 '압축' 대상으로 표시하지만 실제로 줄인 파일을 만들지 않는다.
- **데이터 보존 정리.** 종료 후 1년이 지난 여행방은 기기에서 부팅 때 지우고, 동기화 서버도 시작 때와 하루 한 번 같은 기준
  (종료일 다음 날 00:00 KST + 365일)으로 지운다. 루프백 저장분은 정리하지 않는다. 위치 로그는 기기에만 있고 90일 뒤 지운다.
- **명세 미결정은 보수적 기본값이다.** 방장 위임 없음(방장 나가기 막음), 초대 승인 없음, 그룹원 위치 공유 없음('꺼짐 · 미결정'),
  승격은 userId 유지, 사진은 단말에만, 경로 API 예산은 재계산 1회 100구간 상한과 24시간 캐시. 환율·예산·정산은 명세 밖이라 만들지 않았다.
- **팀 결정으로 명세를 구체화한 곳이 있다.** 지연 조정안은 순서 변경 → 제외 → 체류 줄이기(하나) 순이다. 수동으로 바꾼 순서는
  고정이 아니라서 넘치면 같은 규칙으로 빠진다. 일정 편집은 누르는 즉시 저장한다.
- **화면 눈 확인을 하지 않았다.** 390×844 렌더링, 지도 렌더 2초, 네이티브 기기는 타입 검사·테스트·웹 export로만 확인했다.

## 실제 제공자로 바꾸는 방법

외부 의존은 전부 `src/core/ports.ts`의 중립 인터페이스 뒤에 있고, `src/services/registry.ts`가 키 유무로 구현을 고른다.
화면과 스토어는 어느 구현인지 모른다. 바꾼 뒤에는 더보기 → **제공자 상태**에서 각 항목이 '예시 데이터'에서 실제 제공자 이름으로
바뀌었는지 확인한다.

### 1. 환경 변수

`test/.env.example`을 `test/.env`로 복사해서 채우고 개발 서버를 다시 띄운다. `EXPO_PUBLIC_` 값은 번들을 만들 때 코드에 박히므로
웹 export도 다시 뽑아야 한다.

| 변수 | 있으면 | 없으면 |
| --- | --- | --- |
| `EXPO_PUBLIC_API_URL` | 장소 검색(카카오 로컬)·자동차 경로(카카오모빌리티)·도로 모양을 키 숨기는 서버(`npm run server`)를 거쳐 받는다. 카카오 키는 서버에만. 계정(가입·로그인)도 이 서버의 `/auth`로 간다(메일함은 서버 `AUTH_DEV_OUTBOX=1`일 때만) | 아래 직접 호출 또는 로컬 |
| `EXPO_PUBLIC_KAKAO_REST_KEY` | 시연 한정 직접 호출. 장소는 카카오 로컬, 자동차는 카카오모빌리티. `API_URL`이 있으면 쓰지 않는다(값이 있으면 번들에 들어가니 비운다) | 로컬 장소 사전 |
| `EXPO_PUBLIC_AI_PROXY_URL` | 채팅 추출·추천·일기 문장이 AI 프록시를 거친다 | 규칙 기반·로컬 점수·템플릿 |
| `EXPO_PUBLIC_SYNC_URL` | 그룹 동기화가 HTTP 폴링 서버(보통 `API_URL`과 같은 주소). 계정도 `API_URL`이 없으면 이 서버의 `/auth`를 쓴다(메일함은 서버 `AUTH_DEV_OUTBOX=1`일 때만) | 이 기기 안의 루프백 전송, `API_URL`도 없으면 모의 인증 |
| `EXPO_PUBLIC_KAKAO_MAP_JS_KEY` | 바탕 지도가 카카오맵(기본). 카카오 앱의 JavaScript 키(REST 키 아님). 웹은 카카오맵 SDK, 앱은 WebView 안의 같은 SDK(2-0) | 아래 구글 키가 있으면 구글, 없으면 기본 지도(SVG 격자) |
| `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` | 카카오 키가 없을 때(또는 `MAP_PROVIDER=google`) 구글 지도(웹 Maps JavaScript API, 앱 react-native-maps) | 기본 지도(SVG 격자) |
| `EXPO_PUBLIC_MAP_PROVIDER` | `svg`면 키가 있어도 기본 지도, `google`이면 구글 키가 있을 때 구글, `kakao`는 비운 것과 같다 | 카카오 키, 구글 키, 기본 지도 순서 |
| `EXPO_PUBLIC_ROAD_SHAPE` | `off`(또는 `false`·`0`·`no`·`none`)면 선은 직선, 시간은 구간표·직선 추정(외부 호출 0). OSRM 서버 주소면 그 서버 | 도보·자동차 시간과 선을 OSRM에서(`API_URL`이 있으면 서버의 `/osrm`, 없으면 공개 서버) |
| `EXPO_PUBLIC_GOOGLE_OAUTH_WEB_CLIENT_ID` | 웹에서 실제 구글 로그인(서버 `GOOGLE_OAUTH_CLIENT_ID`와 같은 값, 4-1절). `_ANDROID_`·`_IOS_`는 앱 개발 빌드용(선택) | 구글 로그인 버튼이 키가 없다고 알리고 모의 동의로 이어 간다 |
| `EXPO_PUBLIC_KAKAO_OAUTH_CLIENT_ID` | 실제 카카오 로그인(카카오 앱 REST API 키, 서버 `KAKAO_OAUTH_CLIENT_ID`와 같은 값) | 카카오 로그인 버튼이 키가 없다고 알리고 모의 동의로 이어 간다 |

앱 개발 빌드의 구글 지도 키(`GOOGLE_MAPS_ANDROID_API_KEY`, `GOOGLE_MAPS_IOS_API_KEY`)는 `EXPO_PUBLIC_`이 아니고 `app.config.js`가
빌드 때 읽는다. 서버 변수는 `server/.env`(아래 4절)다.

### 2. 카카오 (장소·자동차 경로)

1. 카카오 개발자 콘솔에서 앱을 만들고 REST API 키를 받는다. 카카오모빌리티 길찾기는 별도 사용 설정이 필요할 수 있다.
2. `EXPO_PUBLIC_KAKAO_REST_KEY=`에 넣는다.
3. 호출하는 곳은 세 군데다. 헤더는 `Authorization: KakaoAK {REST 키}`다(`src/services/kakaoHttp.ts`).
   - 키워드 검색 `https://dapi.kakao.com/v2/local/search/keyword.json`: 수동 등록, 대화 인식 장소 찾기. 지역 반경 안이 0건이면
     반경 없이 한 번 더 찾아 목적지 밖 확인에 쓴다(`src/services/places/kakao.ts`).
   - 카테고리 검색 `https://dapi.kakao.com/v2/local/search/category.json`: 빈 시간 주변 추천.
   - 자동차 길찾기 `https://apis-navi.kakaomobility.com/v1/directions`: 구간 단위로 부르고 24시간 캐시한다(`src/services/routes/kakao.ts`).

주의할 것:

- **프로토타입 가정**이다. 바탕 지도는 카카오맵으로 정했다(2026-10-10). 구글 지도는 선택 대체, 키가 없으면 기본 SVG 지도다.
  카카오맵 JavaScript 키는 REST 키와 다르다(2-0).
- 키는 서버에 두는 것이 기본이다. `server/.env`의 `KAKAO_REST_KEY`에 넣고 앱에는 `EXPO_PUBLIC_API_URL`만 준다(4절).
  `EXPO_PUBLIC_KAKAO_REST_KEY`는 번들에 그대로 들어가므로 시연 한정 직접 호출로만 남겨 두었다.
- 서버 경유에서 카카오가 실패하면(서버에 키 없음, 일시 503·429·5xx·401·403, 서버에 닿지 못함, 시간 초과) 장소는 로컬 장소 사전,
  자동차는 OSRM 실제 길 또는 구간표·직선 추정으로 넘어간다. 일시 실패의 대체 결과는 캐시하지 않아서 카카오가 돌아오면 바로 카카오로 돌아간다.
- 서버에 카카오 키가 없다는 답(503 kakaoDisabled)이면 자동차는 5분(실제 시각) 동안 카카오에 묻지 않는다. 그동안 대체 제공자가
  제대로 낸 값(임시 결과가 아닌 것)은 10분만 캐시한다. 서버에 키를 넣으면 자동차 구간은 10분쯤 안에 카카오로 돌아간다.
- 더보기 → 제공자 상태 아래 안내는 서버가 카카오를 못 써도 도로 경로가 켜져 있으면 이동 시간과 길은 실제 길이라고 한다.
  서버 경유인데 앱 `.env`의 카카오 키가 번들에 남으면 비워 두라고 알린다.
- 시연 구간표에 있는 자동차 구간은 카카오가 있어도 구간표 시간이다. 선·거리·안내 줄만 카카오에서 받는다.
- 실키, 웹 CORS, 동시 요청 한도는 확인하지 못했다(테스트는 가짜 fetch로만 했다).
- 시연 수치(후보 14·확정 11·제외 3)는 서버에 카카오 키를 넣지 않은 상태에서 확인한다. 시나리오 채우기의 장소가 카카오 결과로 바뀔 수 있다.

### 2-0. 카카오맵 (바탕 지도, 기본)

2026-10-10 결정으로 바탕 지도를 구글에서 카카오맵으로 바꿨다. 구글 어댑터는 지우지 않고 선택 대체로 남겼다.

1. [Kakao Developers](https://developers.kakao.com)에서 내 애플리케이션을 만든다(장소 검색·로그인에 쓰는 앱과 같아도 된다).
2. 앱 설정 → **앱 키** → **JavaScript 키**를 복사한다. REST API 키가 아니다(REST 키로는 지도 SDK가 뜨지 않는다).
3. 앱 설정 → **플랫폼** → **Web** → 사이트 도메인에 아래 둘을 등록한다.
   - `http://localhost:8090` (웹 미리보기 `npm run web`)
   - `https://localhost` (앱. WebView가 이 출처로 페이지를 띄운다. https라 SDK·타일 요청도 모두 https다)
   배포 주소가 생기면 그 주소도 넣는다. 등록하지 않은 도메인에서는 SDK가 지도 코드를 주지 않는다.
4. 카카오맵 사용 설정이 꺼져 있으면 제품 설정에서 카카오맵(지도) 사용을 켠다(콘솔 화면에 따라 다르다).
5. `test/.env`에 `EXPO_PUBLIC_KAKAO_MAP_JS_KEY=JavaScript 키`를 넣고 개발 서버를 다시 띄운다.
6. 더보기 → 제공자 상태에 `지도 · 카카오맵`이 보이면 된다.

어떻게 붙어 있는지:

- 엔진 순서는 `EXPO_PUBLIC_MAP_PROVIDER=svg`면 기본 지도, `google`이고 구글 키가 있으면 구글, 그 밖에는 카카오 키, 구글 키, 기본 지도 순서다
  (`src/core/map/engine.ts` `pickMapEngine`).
- 웹은 `src/components/map/KakaoMapView.web.tsx`다. SDK를 `autoload=false`로 한 번 받아 `kakao.maps.load`로 띄운다(`kakaoScript.ts`).
  핀·묶음·현재 위치·이동 점은 CustomOverlay에 기본 지도와 같은 그림(`src/ui/mapPinSvg.ts`)을 얹고, 묶음은 우리 규칙(`core/map/layout`)이다
  (카카오 클러스터러를 쓰지 않는다). 선은 Polyline(점선은 `shortdash`), 정확도 원은 Circle, 화면 맞춤은 `setBounds`에 위·오른쪽·아래·왼쪽 여백이다.
- 앱은 `src/components/map/KakaoMapView.tsx`다. react-native-webview 안에 같은 SDK 페이지(`kakaoHtml.ts`)를 `https://localhost` 출처로 띄우고,
  마커·선·맞춤은 앱에서 페이지로, 핀 누름·지도 누름·움직임·실패는 페이지에서 앱으로 메시지를 보낸다. 묶음은 페이지가 알려 준 화면 좌표로 앱이 계산한다.
- 손짓: 화면 가득한 지도는 끌기·휠 확대, 스크롤 화면 안의 지도는 끌기와 두 손가락·더블클릭 확대만 되고 그냥 휠은 페이지를 스크롤한다
  (Ctrl·Cmd+휠은 확대. 트랙패드 핀치처럼 잘게 오는 휠은 양을 쌓아 한 단계씩 바꾼다). 키보드는 지도나 핀에 포커스가 있을 때
  방향키로 옮기고 +·- 키로 확대·축소한다. 미리보기는 움직이지 않는다. 지도에서 선택은 0.3초 기다렸다 고르고 더블클릭이면 취소한다.
- 실패: SDK를 못 받으면(script), `kakao.maps.load` 콜백이 10초 안에 안 오면(auth, 키 거부·도메인 미등록) "카카오 지도를 불러오지 못해
  기본 지도로 보여 드려요"를 한 번 띄우고 그 세션은 기본 지도다. 10초는 SDK 스크립트를 받은 뒤부터 센다(앱은 화면이 가려진 동안 미룬다). 첫 타일이 10초(보이는 동안만 잼) 안에 안 오면 그 지도 하나만 기본 지도다.

한계:

- 카카오맵은 구글 JSON 스타일 같은 바탕 색 바꾸기가 없다. 바탕은 카카오 기본 일반 지도(유채색)이고 핀·선만 목업과 같다.
- 키 거부와 느린 네트워크를 SDK가 구별해 알려 주지 않아 둘 다 10초 시한으로 잡는다(auth로 본다).
- 스크롤 화면 안의 지도도 한 손가락 끌기가 지도를 움직인다(구글 cooperative의 '두 손가락으로 이동'에 해당하는 옵션이 없다).
- 앱 WebView는 기기에서 아직 확인하지 않았다. 출처를 `https://localhost`로 두어 SDK와 타일이 https로만 오게 했다
  (안드로이드 9 이상 평문 차단, iOS ATS에 걸리지 않게). 예전에 `http://localhost`만 등록했다면 `https://localhost`를 더 넣는다. 실기기 확인이 남아 있다.
- 앱 WebView 안에서 카카오 로고·저작권 링크를 누르면 지도 칸이 바뀌지 않고 바깥 브라우저로 열린다. 다리 페이지가 아닌 문서의 메시지는 버린다.
- 앱 WebView가 다시 뜨면(iOS 웹 프로세스 종료, 안드로이드 렌더러 재시작) 선·핀·맞춤을 다시 보낸다. 렌더러가 거듭 죽으면 그 지도만 기본 지도다.
- JavaScript 키는 번들에 그대로 들어가는 공개 값이다. 등록한 Web 도메인에서만 쓰이므로 도메인 목록을 좁게 둔다.

### 2-1. 구글 지도 (바탕 지도, 선택 대체)

카카오 키가 없을 때, 또는 `EXPO_PUBLIC_MAP_PROVIDER=google`일 때 쓴다.


1. [Google Cloud 콘솔](https://console.cloud.google.com/google/maps-apis)에서 프로젝트를 만들고 결제 계정을 연결한다.
   결제 계정이 없으면 키가 있어도 지도가 뜨지 않는다. 무료 한도 안에서는 청구되지 않는다.
2. **Maps JavaScript API**를 사용 설정하고 API 키를 만든다. 앱 개발 빌드까지 쓰려면 Maps SDK for Android·iOS도 켠다.
3. 키 제한을 건다. 웹 키는 애플리케이션 제한을 "웹사이트"로 두고 `http://localhost:8090/*`와 배포 주소만 넣는다.
   API 제한은 Maps JavaScript API만 고른다.
4. `test/.env`에 `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY=발급받은 키`를 넣고 개발 서버를 다시 띄운다.
5. 더보기 → 제공자 상태에 `지도 · 구글 지도`가 보이면 된다.

무료 한도(2025년 3월 개편 기준): 웹 동적 지도는 월 10,000회 로드, 앱 지도(Maps SDK for Android·iOS)는 무제한이다.
넘으면 과금되므로 콘솔에서 할당량 상한을 걸어 둔다.

어떻게 붙어 있는지:

- `src/components/map/MapCanvas.tsx`가 엔진을 고른다(`src/core/map/engine.ts`). 화면은 전부 MapCanvas만 쓰므로 11 지도, 13 길찾기,
  19 여행 진행, 22 기록 지도, 07 스팟 미리보기, 06 지도에서 선택이 한꺼번에 바뀐다.
- 웹은 `GoogleMapView.web.tsx`다. 스크립트를 한 번 불러오고, 무채색 바탕 스타일(`src/ui/mapStyle.ts`) 위에 기본 지도와 같은 핀
  (`src/ui/mapPinSvg.ts`)을 얹는다. 밀집 핀 묶음, `전체 보기`, 지도 눌러 장소 고르기도 같다.
- 앱은 `GoogleMapView.tsx`(react-native-maps)다. 위 키를 넣으면 안드로이드 Expo Go에서도 구글 지도가 뜬다(네이티브 키는 Expo Go 것을 쓴다).
  iOS Expo Go에는 구글 지도 SDK가 없어 Apple 지도로 그린다.
  개발 빌드에서는 `app.config.js`가 `GOOGLE_MAPS_ANDROID_API_KEY`·`GOOGLE_MAPS_IOS_API_KEY`를 네이티브 설정에 넣는다.
  웹 키를 대신 쓰지 않는다. 웹 키는 웹사이트·Maps JavaScript API로 제한하므로 Maps SDK for Android·iOS가 거부한다.
  플랫폼마다 따로 키를 만들어 패키지 이름+SHA-1(안드로이드), 번들 ID(iOS)로 제한한다. 안드로이드 키 없이 만든 개발 빌드는 기본 지도를 쓴다.
- 키가 거부되거나 스크립트를 못 받으면 "구글 지도를 불러오지 못해 기본 지도로 보여 드려요" 안내를 띄우고 그 세션은 기본 지도로 돌아간다.
  타일이 10초 안에 안 오면 그 지도 하나만 기본 지도로 돌아간다. 시간은 화면이 보이고 지도 칸에 크기가 있을 때만 잰다(숨은 탭에서는 멈춘다).
  구글은 키 없는 요청을 ApiProjectMapError로 막기 때문에 키 없이는 구글 지도를 고르지 않는다.
- 데모 키(Maps Demo Key)는 하루 사용량이 정해져 있다. 지도를 띄울 때마다 한 번으로 센다. 다 쓰면 다음 날까지 기본 지도로 보일 수 있다.
- 웹 키도 번들에 그대로 들어간다. 그래서 리퍼러 제한이 꼭 필요하다.
- 화면 맞춤은 그날 루트(확정 스팟·기점·선) 기준이다. 멀리 떨어진 제외 스팟은 핀만 그리고 맞춤에서 뺀다.
  '전체 보기'는 사용자가 직접 끌거나 확대했을 때(휠·두 손가락·더블클릭·방향키)와 묶음을 눌렀을 때만 뜬다.
- 손짓: 화면 가득한 지도(지도 탭, 길찾기)는 한 손가락으로 움직인다. 스크롤 화면 안의 지도(여행 진행, 기록 지도, 지도에서 선택)는
  두 손가락(웹은 Ctrl+휠)으로 움직여 페이지 스크롤을 가로채지 않는다. 미리보기(스팟 상세)는 움직이지 않는다.
- 지도에서 선택은 누른 뒤 0.3초 기다렸다 고른다. 더블클릭으로 확대하면 고르지 않는다.
- 웹 기본 지도(SVG)는 누르기에 `onClick`과 `onPress: null`을 같이 준다. react-native-svg 15 웹은 `onPress`가 null이 아니면
  `onClick`을 덮어써 핀·묶음·지도에서 선택이 모두 죽는다(2026-10-10 수정).

2026-10-05 실제 키로 웹에서 확인한 것: 지도 탭(날짜 바꾸면 다시 맞춤, 묶음 눌러 확대, 전체 보기, 핀 누르면 스팟 상세),
스팟 상세 미리보기, 후보 '지도에서 선택'(불국사 옆을 누르면 불국사를 찾음), 여행 진행(현재 위치 점이 움직여도 화면 유지),
길찾기, 기록 지도(이동 점). 화면은 `docs/screenshots/google-map-2026-10-05/`에 있다. 앱(react-native-maps)은 실기기에서 아직 확인하지 않았다.
경로 선은 실제 길을 따른다(2026-10-07). 구글 길찾기는 국내 도보·자동차 경로를 주지 않아서 OpenStreetMap 길 데이터를 쓴다.

- 서버: FOSSGIS 공개 OSRM(`routing.openstreetmap.de`, 키 불필요, CORS 허용). 도보는 `routed-foot`, 자동차는 `routed-car`다.
  대중교통은 노선 데이터가 없어 자동차 길 모양을 빌린다(시간·안내 줄은 모의 모델 그대로).
- 바뀌는 것: 지도 선 모양, 길찾기 거리, 안내 줄('좌회전 · 보문로'), 그리고 2026-10-09부터 계획 시간.
  계획 행렬(matrix)은 표에 없는 구간을 OSRM table(`/table/v1`)로 묻는다. 좌표는 요청 하나에 50개까지이고, 넘으면 상한 안에서
  출발지 여럿씩 묶어 나눠 묻는다.
  경로(route)는 그 경로의 duration을 같은 식(자동차 × 1.3)으로 분으로 바꾼다. 같은 구간이면 경로 캐시(`src/services/routes/cache.ts`)가
  먼저 받은 값으로 행렬과 경로의 분을 맞춘다. 호출 수(routeCalls)는 요청 수가 아니라 구간 수로 세어 재계산 1회 100구간 예산을 지킨다.
- 구간마다 24시간 캐시에 둔다. 서버가 실패하거나(503, 다른 400, 시간 초과는 직접 8초·서버 경유 15초, 읽을 수 없는 응답) 답하지 않으면
  그 행렬·구간은 직선 추정이고, 캐시에 두지 않아 다음에 다시 묻는다. 길로 못 잇는 구간(table의 null 칸, 400 NoRoute·NoSegment)은
  직선 추정으로 두고 캐시한다. 시간 제한은 본문을 다 받을 때까지다. 200인데 본문을 읽지 못하거나 표가 요청과 다르면 실패로 보고
  아래 쉬는 시간(60초)도 시작한다.
- **쉬는 시간(2026-10-09 추가).** 경로 서버가 429·5xx를 주거나 닿지 않거나 시간이 넘으면 60초(실제 시각) 동안 묻지 않고 바로
  직선 추정으로 넘어간다(`OSM_COOLDOWN_MS`). 공개 서버에 직접 묻는 table은 4초에서 끊는다(`OSM_TABLE_TIMEOUT_MS`).
  수정 전에는 공개 서버가 429를 주다 연결을 끊는 동안 계획이 구간마다 다시 두드려 100구간 계산이 90.5초 걸렸다. 지금은 몇 번만 묻고 끝난다.
- 계획기는 출발지·수단이 같은 구간을 묶어(목적지 12곳까지) 한 번에 묻는다(`src/core/planner/travel.ts`). 100구간 시나리오면
  table 요청이 25번쯤이다. 호출 수(routeCalls)는 그대로 구간 수로 센다. 그래도 공개 서버는 금방 요청 제한(429)에 걸리므로
  시연은 서버 중계(동시 2개, 24시간 캐시)를 쓰는 편이 좋다.
- 같은 구간을 동시에 물으면(경로 비교 화면, 미리보기 계획 두 개) 한 번만 묻고 답을 나눠 쓴다.
- 스팟·기점 좌표가 이 서버(독일 FOSSGIS)로 간다. 현재 위치는 보내지 않는다. 공개 서버는 가벼운 사용만 허용하므로 실서비스는
  자체 OSRM 서버(`EXPO_PUBLIC_ROAD_SHAPE=https://내-서버`)나 국내 경로 API(TMAP 보행자, 카카오모빌리티)로 옮긴다.
- 길 데이터 출처(OpenStreetMap 기여자, ODbL)를 지도 탭·여행 진행·길찾기에 적는다.
- 카카오(서버 경유 또는 키)가 있으면 자동차는 카카오모빌리티가 먼저다(도보 시간·선은 그대로 OpenStreetMap, 대중교통 선은 자동차 길을 빌린다).
- 여행 시뮬레이터 점도 이 길을 따라간다(2026-10-09, 위 '여행 시뮬레이터 사용법').
- 지도·길찾기의 복귀 구간(마지막 스팟 → 기점)은 계획의 복귀 구간(`DayPlan.returnLeg`) 수단과 추정 표시를 따른다.
- 지연 조정안은 지금 위치에서 출발하는 구간을 경로 서버에 묻지 않고 기기 안에서 직선거리로 추정한다. GPS는 서버·카카오·OSRM으로 나가지 않는다.
  스팟·기점에 있을 때(소수 5자리까지 같은 좌표)는 받은 GPS 값이 아니라 그 스팟·기점 좌표 그대로 묻는다.
- 경로 캐시 색인은 v2이고 제공자 서명(도로 경로 켬·주소, 카카오 방식, 자동차 보정 계수, 예시 구간표 해시)을 함께 둔다.
  `EXPO_PUBLIC_ROAD_SHAPE`, `EXPO_PUBLIC_API_URL`, 카카오 방식(서버·직접 키·없음), 구간표가 바뀌면 예전 항목을 모두 버린다.
  캐시 시계는 시뮬레이터 가상 시각이 아니라 실제 시계(`systemClock`)다.

화면은 `docs/screenshots/road-route-2026-10-07/`에 있다.

### 3. AI 프록시 (추출·추천·일기)

AI 키는 프록시 서버에만 둔다. 앱은 브라우저에서 AI 제공자를 직접 부르지 않는다. 프록시는 아래 세 경로를 JSON으로 받고 JSON으로
답하면 된다(`src/services/aiProxy.ts`, `POST {EXPO_PUBLIC_AI_PROXY_URL}{경로}`). 웹에서 쓰려면 CORS 헤더와 OPTIONS 응답이 필요하다.

| 경로 | 요청 본문 | 응답 | 실패하거나 모양이 틀리면 |
| --- | --- | --- | --- |
| `/extract` | `{text, region:{id,name}}` | `{phrases:[{phrase, start?, end?}]}` | 규칙 기반 추출. 응답은 원문 부분 문자열로 다시 맞춘다 |
| `/recommend` | `{region:{id,name}, dates, tags, existing:[placeId], limit}` | `{items:[{place, reason}], fallback}` | 로컬 추천. 기존 후보·지역 밖·형식 오류를 거르고 3곳 미만이면 로컬 |
| `/diary` | `{date, blocks}` | `{texts:[문장]}`(블록 수와 같게) | 빈 일기. 15초 안에 답이 없어도 빈 일기 |

`place`는 `src/types.ts`의 `Place` 모양(placeId, name, coord{latitude,longitude}, category 등)이다. 실제 프록시로는 아직 확인하지 못했다.

### 4. 동기화·중계 서버 (`test/server`)

한 서버가 그룹 동기화와 키 숨기는 중계(카카오·OSRM)를 같이 한다. Node 24, node:http, DB 드라이버 pg다.

```bash
cp server/.env.example server/.env   # 값은 직접 넣는다. 채팅·이슈에 붙이지 않는다
npm run db:up                        # PostgreSQL을 쓸 때만(Docker 필요, postgres:17-alpine, 127.0.0.1:5432)
npm run server                       # = node --env-file-if-exists=server/.env server/sync-server.mjs, 포트 8787
npm run db:down                      # DB 끄기(데이터는 볼륨에 남는다)
```

앱 `test/.env`에는 `EXPO_PUBLIC_SYNC_URL`과 `EXPO_PUBLIC_API_URL`을 `http://<이 컴퓨터 IP>:8787`로 넣는다(`localhost`는 폰에서 안 된다).
그러면 가입·로그인도 이 서버로 간다. 혼자 쓰는 개발 서버에서 이메일 인증·모의 소셜까지 해 보려면 `server/.env`에 `AUTH_DEV_OUTBOX=1`을 넣는다.
시작 로그에 '저장: PostgreSQL|메모리'와 '중계: 카카오 켜짐/꺼짐, OSRM <주소>', '계정: … 보낸편지함·모의 소셜 열림|닫힘'이 찍힌다. `GET /health`는 `{ok, db}`다(DB에 못 닿으면 503).

| 서버 변수(`server/.env`) | 뜻 |
| --- | --- |
| `DATABASE_URL` | 있으면 PostgreSQL, 비우면 메모리(서버를 끄면 사라진다). 값이 있는데 붙지 못하면 시작하지 않는다 |
| `PORT` | 기본 8787 |
| `SYNC_ALLOW_RESET` | `1`이면 시연 리셋(`POST /reset`)이 서버 여행방을 모두 지운다. PostgreSQL 모드에서만 본다. 혼자 쓰는 DB에서만 켠다 |
| `KAKAO_REST_KEY` | 서버에만 둔다. 없으면 `/kakao/…`는 503이고 앱은 로컬로 넘어간다 |
| `OSRM_URL` | 기본 `https://routing.openstreetmap.de` |
| `OSRM_CONCURRENCY` | 기본 2. 공개 서버에는 설정과 상관없이 2개까지만 보낸다 |
| `PROXY_RATE_PER_MIN` | IP별 분당 요청 상한, 기본 300. 0이면 끈다 |
| `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | 실제 구글 로그인(웹 클라이언트 ID와 비밀번호). 둘 다 있어야 켜진다. 없으면 `/auth/oauth/google`·state는 503 |
| `GOOGLE_OAUTH_NATIVE_CLIENT_IDS` | 앱 개발 빌드의 안드로이드·iOS 구글 클라이언트 ID(쉼표). secret 없이 교환한다(선택) |
| `KAKAO_OAUTH_CLIENT_ID`, `KAKAO_OAUTH_CLIENT_SECRET` | 실제 카카오 로그인(REST API 키, 콘솔에서 Client Secret을 켰을 때만 secret). 키가 없으면 503 |
| `OAUTH_REDIRECT_URIS` | 받는 돌아올 주소(쉼표, 끝 `/` 무시 정확 일치). 비우면 `http://localhost:8090`만. 목록 밖 주소는 400(코드 주입 방지) |
| `AUTH_DEV_OUTBOX` | `1`이면 개발용 보낸편지함(`GET /auth/outbox`)과 모의 소셜(`/auth/social…`)을 연다. `SYNC_ALLOW_RESET=1`이어도 열린다. 메모리 모드라고 열리지 않는다(기본 닫힘, 404). 보낸편지함에 살아 있는 인증·재설정 토큰이 있으므로 공유 서버·LAN에 연 서버에서는 켜지 않는다 |

동기화:

- 받은 순서대로 seq를 매기고 같은 op.id는 한 번만 받는다. 같은 방 push는 차례로 처리된다(seq가 겹치거나 비지 않는다).
- 원천은 `trip_ops`와 `invite_codes`이고, 조회용 표(trips 요약, trip_spots, trip_days, trip_legs)는 push와 같은 트랜잭션에서 갱신한다.
  시간표(plan)는 기기마다 계산하므로 서버에 없다. 위치 테이블은 없다(위치를 서버에 올리지 않는다).
- 스키마는 `server/db/migrations/NNN_이름.sql`이다. 서버 시작 때 안 한 번호만 적용한다. 적용한 파일을 고치면 체크섬이 달라 시작을 멈추므로
  스키마는 새 번호 파일을 더해 바꾼다.
- 보관 기한: 종료일 다음 날 00:00 KST + 365일이 지난 방을 시작 때와 하루 한 번 지운다.
- 동기화 경로(`/trips`, `/invites`)에는 인증이 없다. 실서비스 전에 정해야 한다.

계정(`/auth/…`, `server/auth.mjs`, 표는 `002_auth.sql`의 `auth_*`. 메모리 모드는 같은 규칙을 메모리에):

- 가입 `POST /auth/signup` → 인증 메일 → `POST /auth/verify`가 세션 토큰을 준다. 로그인 `POST /auth/signin`, 세션 `GET /auth/session`,
  로그아웃 `POST /auth/signout`, 프로필 `POST /auth/profile`, 탈퇴 `POST /auth/delete`, 닉네임 `GET /auth/nickname`,
  재설정 `POST /auth/password/reset|confirm`, 모의 소셜 `POST /auth/social`, `POST /auth/social/confirm`,
  실제 소셜 `POST /auth/oauth/state`, `POST /auth/oauth/google|kakao`, `POST /auth/oauth/confirm`(4-1절). 인증이 필요한 곳은 `Authorization: Bearer`.
- 로그인 아이디는 이메일 또는 닉네임이다(`signin`의 `email` 칸에 둘 중 하나). 닉네임은 계정마다 하나이고 `@`를 쓸 수 없다.
  없는 아이디도 같은 계산·같은 문구이고, 이메일·닉네임 어느 쪽으로 틀려도 같은 계정의 연속 실패 칸을 센다.
- 비밀번호는 scrypt(사람마다 salt)만, 세션·메일 토큰은 SHA-256만 저장한다. 세션은 쓸 때마다 30일 연장, 안 쓰면 30일 뒤 만료(앱 시작 때 확인하고 다시 로그인 안내).
- 시도 제한: 이메일 기준 5회 연속 실패 10분 잠금(없는 이메일도 같게), IP 10분 20회, 이메일+IP 10분 10회, 메일 보내기 IP 10분 10통.
  연속 실패 카운터는 비밀번호를 확인하기 전에 원자적으로 먼저 올린다(PostgreSQL은 한 문장 upsert). 여러 IP에서 동시에 보내도 5번까지만 확인한다.
  IP는 연결한 주소다(역방향 프록시 뒤에서는 한 IP로 세어진다).
- 오류 문구는 가입 여부를 드러내지 않는다(가입 때 '이미 가입한 이메일'만 예외). 재발송·재설정 요청은 없는 이메일이어도 ok다.
- 게스트 승격은 앱이 보낸 userId를 그대로 쓴다. 게스트 userId는 여행방 로그로 남에게 보이므로 앱이 기기 토큰을 같이 보내고, 서버는 그 해시
  (`upgrade_proof`)를 둔다. 인증 전 가입은 같은 기기만 대체하고(다른 기기는 409, 기기 토큰 없이 userId만 보내면 400), 1일이 지난 가입은 누구든 대체한다.
  인증한 뒤에는 거부한다. 탈퇴는 행을 남기고 이메일·닉네임·비밀번호·프로필·확인값을 비운다.
- 모의 소셜(`/auth/social`, `/auth/social/confirm`)은 실제 제공자 검증이 없어 개발 서버(`AUTH_DEV_OUTBOX=1` 또는 `SYNC_ALLOW_RESET=1`)에서만 열린다.
  같은 이메일 연결은 계정이 있든 없든 같은 `linkRequired` 응답이고, 확인 토큰은 그 이메일로 보낸 연결 확인 메일(보낸편지함)에만 있다.
  앱은 개발 서버면 그 메일을 모의 메일함에서 대신 열어 26 확인 화면으로 넘긴다. 정상 시나리오의 제공자 신원은 기기 토큰 해시로 흉내 낸다(모의 한정).
- 메일은 보내지 않는다(SMTP 없음, 추후 과제). 개발용 보낸편지함은 서버 메모리에만 있고 `AUTH_DEV_OUTBOX=1`·`SYNC_ALLOW_RESET=1`일 때만 읽힌다(기본 닫힘).
- 비밀번호·토큰·요청 본문은 로그에 남기지 않는다.

중계(모두 GET, CORS 허용):

- `/kakao/local/keyword`, `/kakao/local/category`, `/kakao/navi/directions`, `/osrm/routed-{foot,car}/{route,table}/v1/…`
- 허용 목록 밖 매개변수와 국내 범위(경도 124~132, 위도 33~39) 밖 좌표는 400, 요청 줄 4KB 초과는 414, GET이 아니면 405다.
- OSRM과 카카오 길찾기 200 응답만 24시간 캐시한다(PostgreSQL `route_cache` 또는 메모리 2000개). 장소 검색은 캐시하지 않는다.
- 공개 OSRM에는 동시 2개까지만 보내고, 차례를 6초 안에 못 받으면 503 busy다. 상류 시간 초과(8초)는 504, 닿지 못하면 502다.
- 요청의 좌표와 검색어는 기록하지 않는다. 응답에 키 글자가 섞이면 가린다.

테스트: `tests/wp2-db.test.ts`는 PGlite(WASM Postgres)로 돈다. 실 PostgreSQL로도 돌리려면
`npm run db:up && YT_TEST_DATABASE_URL=postgresql://youngtrip:youngtrip-dev@127.0.0.1:5432/youngtrip npm test`다
(임시 스키마 `yt_test_*`·`yt_auth_*`를 만들고 끝나면 지운다). 중계는 `tests/wp2-proxy.test.ts`, 앱 쪽은 `tests/wp4-api-proxy.test.ts`다.
계정 서버는 `tests/wp2-auth.test.ts`(메모리·PGlite·실 PostgreSQL), 앱 HTTP 인증 제공자는 `tests/wp1-auth-http.test.ts`다.
실제 소셜 로그인은 `tests/wp2-oauth.test.ts`(가짜 구글·카카오, 세 저장소), 앱 쪽은 `tests/wp1-oauth.test.ts`다.

### 4-1. 실제 소셜 로그인 (구글·카카오 OAuth)

흐름: 로그인 화면이 계정 서버에서 일회용 state를 받아 두고(`POST /auth/oauth/state`, 제공자·돌아올 주소에 묶이고 10분, 해시만 저장),
버튼을 누르면 expo-auth-session이 제공자 로그인 창을 연다(인가 코드 + PKCE S256). 돌아온 코드·code_verifier·state를 서버로 보내면
(`POST /auth/oauth/google|kakao`) 서버가 state와 돌아올 주소 허용 목록을 확인하고 제공자 토큰 주소에서 직접 코드를 바꾼다.
구글은 id_token을 tokeninfo로 다시 확인하고(aud·iss·exp), 카카오는 `kapi.kakao.com/v2/user/me`로 회원번호를 읽는다.
제공자 신원이 이미 있으면 그 계정, 제공자가 인증한 이메일과 같은 인증된 계정이 있으면 조용히 붙이지 않고 그 이메일로 연결 확인 메일을 보낸다
(`linkRequired`, 확인하면 `POST /auth/oauth/confirm`). 같은 이메일로 인증하지 않은 가입만 있으면 남이 선점한 것일 수 있어 그 가입을 지운다. 아니면 새 계정을 만든다(닉네임은 제공자 이름, 겹치면 숫자). 그다음은 평소 세션 토큰이다.
앱은 제공자 토큰을 보지 않고, client secret은 서버에만 있다. 웹 개발 서버(`npm run web`, 8090) 기준이다. 실제 구글·카카오와의 왕복은
아직 키를 넣고 확인하지 않았고, 서버 쪽은 가짜 제공자 테스트로 확인했다. 앱 개발 빌드는 아래 주의를 본다.

어떤 값이 어디로 가나:

| 값 | 앱 `test/.env` | 서버 `server/.env` |
| --- | --- | --- |
| 구글 웹 클라이언트 ID | `EXPO_PUBLIC_GOOGLE_OAUTH_WEB_CLIENT_ID` | `GOOGLE_OAUTH_CLIENT_ID`(같은 값) |
| 구글 클라이언트 보안 비밀번호 | 넣지 않는다 | `GOOGLE_OAUTH_CLIENT_SECRET` |
| 구글 안드로이드·iOS 클라이언트 ID(선택) | `EXPO_PUBLIC_GOOGLE_OAUTH_ANDROID_CLIENT_ID`, `_IOS_CLIENT_ID` | `GOOGLE_OAUTH_NATIVE_CLIENT_IDS` |
| 카카오 REST API 키 | `EXPO_PUBLIC_KAKAO_OAUTH_CLIENT_ID` | `KAKAO_OAUTH_CLIENT_ID`(같은 값) |
| 카카오 Client Secret(켰을 때만) | 넣지 않는다 | `KAKAO_OAUTH_CLIENT_SECRET` |
| 돌아올 주소 | (웹은 지금 주소의 origin, 자동) | `OAUTH_REDIRECT_URIS`(기본 `http://localhost:8090`) |

앱에는 계정 서버 주소(`EXPO_PUBLIC_API_URL` 또는 `EXPO_PUBLIC_SYNC_URL`)도 있어야 한다. 없으면(이 기기 모의 인증) 버튼은 실제 로그인을 하지 않고
'계정 서버가 있어야 한다'고 알린 뒤 모의 동의 화면으로 이어 간다. 키를 바꾸면 서버와 앱을 둘 다 다시 띄운다. 서버 시작 로그에
'소셜 로그인(OAuth): 구글 켜짐|꺼짐, 카카오 켜짐|꺼짐, 돌아올 주소 …'가 찍힌다(값은 찍지 않는다).

구글 OAuth 클라이언트 만들기:

1. [Google Cloud 콘솔](https://console.cloud.google.com/apis/credentials) → 프로젝트 선택 → OAuth 동의 화면(Google 인증 플랫폼)을 먼저 만든다.
   사용자 유형은 외부, 범위는 `openid`·`email`·`profile`. 게시 전(테스트 중)에는 테스트 사용자로 넣은 구글 계정만 로그인된다.
2. 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 애플리케이션 유형 **웹 애플리케이션**.
3. 승인된 자바스크립트 원본: `http://localhost:8090`. 승인된 리디렉션 URI: `http://localhost:8090` (끝 `/` 없이, 배포 주소가 있으면 같이).
4. 만든 클라이언트 ID는 앱 `EXPO_PUBLIC_GOOGLE_OAUTH_WEB_CLIENT_ID`와 서버 `GOOGLE_OAUTH_CLIENT_ID`에, 보안 비밀번호는 서버 `GOOGLE_OAUTH_CLIENT_SECRET`에만 넣는다.

카카오 앱 만들기:

1. [Kakao Developers](https://developers.kakao.com/console/app) → 애플리케이션 추가. 앱 키의 **REST API 키**가 client_id다.
2. 제품 설정 → 카카오 로그인 → 활성화 ON. Redirect URI에 `http://localhost:8090`을 등록한다(끝 `/` 없이).
   앱 설정 → 플랫폼 → Web 사이트 도메인에도 `http://localhost:8090`을 넣는다.
3. 동의항목: 닉네임(필수 또는 선택), 카카오계정(이메일)(선택 동의 이상. 비즈 앱 전환 전에는 이메일 동의항목이 막혀 있을 수 있다).
   이메일이 없거나 카카오가 인증하지 않은 이메일이면 기존 계정과 잇지 않고 새 계정을 만든다(이메일 없는 계정은 비밀번호 재설정을 쓸 수 없다).
4. 보안 → Client Secret: 켜면 코드를 만들고 활성화 상태를 '사용함'으로 둔 뒤 서버 `KAKAO_OAUTH_CLIENT_SECRET`에 넣는다. 끄면 비워 둔다.
5. REST API 키를 앱 `EXPO_PUBLIC_KAKAO_OAUTH_CLIENT_ID`와 서버 `KAKAO_OAUTH_CLIENT_ID`에 넣는다. REST API 키는 로그인 주소에 그대로 실리는
   공개 값이지만, 장소 검색용 `KAKAO_REST_KEY`(서버)·`EXPO_PUBLIC_KAKAO_REST_KEY`와는 따로 둔다(같은 키여도 된다).

주의:

- 돌아올 주소는 제공자 콘솔·서버 `OAUTH_REDIRECT_URIS`·실제 앱 주소가 글자 하나까지 같아야 한다(웹은 `window.location.origin`).
  `http://127.0.0.1:8090`으로 열면 다른 주소다. LAN IP나 배포 주소로 열면 세 곳에 모두 더한다.
- 웹 로그인 창은 팝업이다. 브라우저가 팝업을 막으면 이 주소의 팝업을 허용한다.
- 같은 인증 이메일의 계정이 있으면 연결 확인 메일로만 잇는다. 메일 발송(SMTP)이 아직 없어 개발 서버(`AUTH_DEV_OUTBOX=1`)에서만 확인을 마칠 수 있다.
- 앱 개발 빌드(안드로이드·iOS)는 돌아올 주소가 `youngtrip://`이다. 구글은 플랫폼별 클라이언트 ID가, 카카오 REST 로그인은 http(s) 돌아올 주소가 필요해
  아직 확인하지 않았다(Expo Go에서는 동작하지 않는다). 프로필의 '카카오·구글 연결'은 아직 모의 동의 화면이다.

## 확정된 규칙 (되돌리지 않는다)

- 확정 버튼은 없다. 후보 전부를 루트 대상에 넣고 하루 수용량을 넘는 만큼만 자동 제외한다.
  제외 순서는 제안자 수가 적은 순, 동점이면 등록이 늦은 순이다. 고정한 후보는 자동 제외하지 않는다.
- 1단계 이동수단은 도보·자동차, 대중교통은 2차 확장이다.
- 국내 전용, 지도 SDK 중립 인터페이스, 게스트 세션(기기 토큰 + 닉네임, 30일, 사용 시 갱신).
- 2·3차 실시간 기능은 여행 시뮬레이터(시각 가속 재생)로 시연한다.
- 사용자 화면 문구에 내부 화면 번호를 쓰지 않는다(더보기 시연 도구의 화면 목록만 예외).
